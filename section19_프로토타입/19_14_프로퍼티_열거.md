# 19.14 프로퍼티 열거

## 19.14.1 for ... in 문

객체 자신과 상위 프로토타입에 있는 열거 가능한 문자열 키를 순회하려면 **`for...in` 문**을 사용한다.

```text
for (변수선언문 in 객체) {...}
```

**예제 19-64**

```js
const person = {
  name: "Lee",
  address: "Seoul",
};

// for...in 문의 변수 key에 person 객체의 프로퍼티 키가 할당된다
for (const key in person) {
  console.log(key + ":" + person[key]);
}

// name: Lee
// address: Seoul
```

`for...in` 문은 객체 자신의 열거 가능한 문자열 키와 상속받은 열거 가능한 문자열 키를 순회한다. 이 예제에서는 해당 키가 `name`, `address` 두 개이므로 두 번 반복한다.
첫 번째 순회에서는 `name`, 두 번째 순회에서는 `address`가 `key` 변수에 할당되고 코드 블록이 실행된다.
`for...in` 문은 `in` 연산자와 마찬가지로 상속된 프로퍼티도 대상으로 삼지만, 실제 열거에서는 `[[Enumerable]]`이 `true`인 문자열 키만 포함한다.

**예제 19-65**

```js
const person = {
  name: "Lee",
  address: "Seoul",
};

// in 연산자는 객체가 상속받은 모든 프로토타입의 프로퍼티를 확인
console.log("toString" in person); // true

// for ... in 문도 객체가 상속받은 모든 프로토타입의 프로퍼티를 열거한다
// 하지만 toString과 같은 Object.prototype의 프로퍼티가 열거되지 않음
for (const key in person) {
  console.log(key + ":" + person[key]);
}

// name: Lee
// address: Seoul
```

`toString` 메서드가 열거 불가능한 프로퍼티로 정의되어 있기 때문이다. 프로퍼티 어트리뷰트 `[[Enumerable]]`은 열거 가능 여부를 나타내는 불리언 값이다.
**예제 19-66**

```js
// Object.getOwnPropertyDescriptor 메서드는 프로퍼티 디스크립터 객체를 반환
// 프로퍼티 디스크립터 객체는 프로퍼티 어트리뷰트 정보를 담고 있는 객체
console.log(Object.getOwnPropertyDescriptor(Object.prototype, "toString"));
// {value: f, writable: true, enumerable: false, configurable: true }
```

**`for...in` 문은 객체 자신과 프로토타입 체인에 존재하는 프로퍼티 중 `[[Enumerable]]`이 `true`인 문자열 키를 열거한다.**

**예제 19-67**

```js
const person = {
  name: "Lee",
  address: "Seoul",
  __proto__: { age: 20 },
};

for (const key in person) {
  console.log(key + ":" + person[key]);
}

// name: Lee
// address: Seoul
// age: 20
```

`for...in` 문은 프로퍼티 키가 `Symbol`인 프로퍼티를 열거하지 않는다.
**예제 19-68**

```js
const sym = Symbol();
const obj = {
  a: 1,
  [sym]: 10,
};

for (const key in obj) {
  console.log(key + ":" + obj[key]);
}

// a : 1
```

자신의 프로퍼티만 열거하려면 `Object.hasOwn` 등으로 고유 프로퍼티인지 확인할 수 있다.

**예제 19-69**

```js
const person = {
  name: "Lee",
  address: "Seoul",
  __proto__: { age: 20 },
};

for (const key in person) {
  // 객체 자신의 프로퍼티인지 확인
  if (!Object.hasOwn(person, key)) {
    continue;
  }
  console.log(key + " : " + person[key]);
}
```

`person` 객체의 문자열 키는 생성된 순서대로 열거되었다. 일반 객체에서 정수 인덱스 형태의 키는 오름차순으로, 나머지 문자열 키는 생성 순서로 처리된다. 단, 순회 도중 객체를 변경하거나 특수 객체를 사용하는 경우에는 주의해야 한다. 순서가 중요한 데이터는 배열이나 `Map`처럼 목적에 맞는 자료구조를 고려한다.

**예제 19-70**

```js
const obj = {
  2: 2,
  3: 3,
  1: 1,
  b: "b",
  a: "a",
};

for (const key in obj) {
  if (!Object.hasOwn(obj, key)) {
    continue;
  }
  console.log(key + " : " + obj[key]);
}

/*
1: 1
2: 2
3: 3
b: b
a: a
*/
```

배열 요소를 순회할 때는 `for...in`보다는 `for`, `forEach`, `for...of`를 권장한다. 배열도 객체이므로 `for...in`에는 인덱스 외의 프로퍼티와 상속된 열거 가능한 프로퍼티가 포함될 수 있다.

**예제 19-71**

```js
const arr = [1, 2, 3];
arr.x = 10; // 배열도 객체므로 프로퍼티를 가질 수 있다

for (const i in arr) {
  // 프로퍼티 x도 출력된다
  console.log(arr[i]); // 1 2 3 10
};

// arr.length는 3
for (let i = 0; i < arr.length; i++) {
  console.log(arr[i]); // 1 2 3
}

// forEach 메서드는 요소가 아닌 프로퍼티는 제외
arr.forEach(v => console.log(v)); // 1 2 3

// for ... of는 변수 선언문에서 선언한 변수에 키가 아닌 값을  할당한다
for (const value of arr) {
  console.log(value); // 1 2 3
};
```

## 19.14.2 Object.keys/values/entries 메서드

`for...in` 문은 객체 자신의 고유 프로퍼티뿐 아니라 상속된 열거 가능한 프로퍼티도 열거하므로 고유 프로퍼티만 필요한 경우 별도의 검사 처리가 필요하다. 이때 `Object.keys`, `Object.values`, `Object.entries`를 사용하는 방법이 편리하다.

`Object.keys`는 객체 자신의 열거 가능한 문자열 키를 배열로 반환한다.

**예제 19-72**

```js
const person = {
  name: "Lee",
  address: "Seoul",
  __proto__: { age: 20 },
};

console.log(Object.keys(person)); // ["name", "address"]
```

**예제 19-73**

```js
console.log(Object.values(person)); // ["Lee", "Seoul"]
```

**예제 19-74**

```js
console.log(Object.entries(person)); // [["name", "Lee"], ["address", "Seoul"]]

Object.entries(person).forEach(([key, value]) => console.log(key, value));
```

## 열거 범위 비교

| API                            | 고유 프로퍼티    | 상속 프로퍼티 | 열거 불가 프로퍼티 | Symbol 키 |
| ------------------------------ | ---------------- | ------------- | ------------------ | --------- |
| `for ... in`                   | 포함             | 포함          | 제외               | 제외      |
| `Object.keys/values/entries`   | 포함             | 제외          | 제외               | 제외      |
| `Object.getOwnPropertyNames`   | 포함             | 제외          | 포함               | 제외      |
| `Object.getOwnPropertySymbols` | Symbol 키만 포함 | 제외          | 포함 가능          | 포함      |
| `Reflect.ownKeys`              | 포함             | 제외          | 포함               | 포함      |

`for...in`은 열거 가능한 문자열 키를 순회하고, `for...of`는 이터러블이 제공하는 값을 순회한다. 일반 객체가 자동으로 이터러블인 것은 아니다.

## 복습 질문과 답변

1. **프로토타입 상속은 메서드를 인스턴스에 복사하는가**

   **답변:** 기본적으로 복사하지 않는다. 인스턴스에서 찾지 못한 프로퍼티를 상위 객체에서 탐색한다.

2. **Person.prototype과 Person 자신의 프로토타입은 같은가**

   **답변:** 다르다. 기본적으로 전자는 인스턴스가 상속할 객체이고, 후자는 `Function.prototype`이다.

3. **constructor로 실제 생성자를 확실히 알 수 있는지**

   **답변:** `constructor`는 변경 가능한 프로퍼티이므로 실제 생성 이력을 보장하지 않는다.

4. **delete me.sayHello는 상속된 메서드도 삭제하는지**

   **답변:** `me` 자신의 프로퍼티만 삭제한다. 상위 메서드를 삭제하려면 해당 프로토타입에 직접 접근해야 한다.

5. **생성자의 prototype을 교체하면 기존 인스턴스도 바뀌는지**

   **답변:** 기존 연결은 유지된다. 현재 `prototype`을 검사하는 `instanceof` 결과는 달라질 수 있다.

6. **Object.create(null)의 특징은?**

   **답변:** `Object.prototype`을 상속하지 않으므로 `toString`, `hasOwnProperty` 등의 상속 메서드도 없다.

7. **`in`과 `Object.hasOwn`은 무엇이 다른지**

   **답변:** `in`은 상속 프로퍼티까지 검사하고, `Object.hasOwn`은 고유 프로퍼티만 검사한다.

8. **배열 순회에 for...in을 피하는 것은**

   **답변:** 인덱스 외 프로퍼티와 상속 프로퍼티까지 열거할 수 있기 때문이다. 배열 요소는 `for...of`, `for`, `forEach` 등으로 순회한다.
