# 17.2 생성자 함수에 의한 객체 생성

## 17.2.1 객체 리터럴에 의한 객체 생성 방식의 문제점

객체 리터럴 방식은 직관적이고 간단하다.

```jsx
const circle1 = {
  radius: 5,
  getDiameter() {
    return 2 * this.radius;
  },
};

console.log(circle1.getDiameter()); // 10
```

하지만 객체 리터럴 방식은 **하나의 객체만 생성**한다.

따라서 동일한 구조의 객체를 여러 개 만들어야 할 때는 같은 프로퍼티와 메서드를 반복해서 작성해야 한다.

```jsx
const circle2 = {
  radius: 10,
  getDiameter() {
    return 2 * this.radius;
  },
};

console.log(circle2.getDiameter()); // 20
```

---

## 핵심 문제

`circle1`과 `circle2`는 구조가 거의 같다.

```js
{
  radius: 값,
  getDiameter() {
    return 2 * this.radius;
  }
}
```

차이는 `radius` 값뿐이다.

하지만 객체 리터럴로 만들면 객체마다 같은 메서드와 프로퍼티 구조를 반복해서 작성해야 한다.

---

## 정리

| 구분   | 설명                                              |
| ------ | ------------------------------------------------- |
| 장점   | 직관적이고 간단하다                               |
| 단점   | 동일한 구조의 객체를 여러 개 만들 때 비효율적이다 |
| 문제점 | 같은 프로퍼티와 메서드를 반복 작성해야 한다       |

---

# 17.2.2 생성자 함수에 의한 객체 생성 방식의 장점

생성자 함수는 동일한 프로퍼티 구조를 가진 객체를 여러 개 만들 때 유용하다.

객체를 생성하기 위한 **템플릿**처럼 사용할 수 있다.

```js
function Circle(radius) {
  this.radius = radius;

  this.getDiameter = function () {
    return 2 * this.radius;
  };
}

const circle1 = new Circle(5);
const circle2 = new Circle(10);

console.log(circle1.getDiameter()); // 10
console.log(circle2.getDiameter()); // 20
```

---

## 생성자 함수의 장점

생성자 함수를 사용하면 객체마다 다른 값만 인수로 전달하면 된다.

```js
const circle1 = new Circle(5);
const circle2 = new Circle(10);
```

즉, 객체 리터럴처럼 같은 구조를 계속 반복해서 작성하지 않아도 된다.

---

## this의 의미

생성자 함수 내부의 `this`는 생성자 함수가 앞으로 생성할 인스턴스를 가리킨다.

```js
function Circle(radius) {
  this.radius = radius;
}
```

위 코드에서 `this.radius`는 새로 생성되는 객체의 `radius` 프로퍼티를 의미한다.

---

## this 바인딩 정리

`this`가 가리키는 값은 함수 호출 방식에 따라 달라진다.

| 함수 호출 방식     | this가 가리키는 값            |
| ------------------ | ----------------------------- |
| 일반 함수로 호출   | 전역 객체                     |
| 메서드로 호출      | 메서드를 호출한 객체          |
| 생성자 함수로 호출 | 생성자 함수가 생성할 인스턴스 |

```js
function foo() {
  console.log(this);
}

foo(); // window 또는 global

const obj = { foo };
obj.foo(); // obj

const inst = new foo(); // inst
```

---

## 주의할 점

생성자 함수도 일반 함수와 형태는 같다.

하지만 `new`와 함께 호출하면 생성자 함수로 동작하고, `new` 없이 호출하면 일반 함수로 동작한다.

```js
const circle3 = Circle(15);

console.log(circle3); // undefined
```

`new` 없이 호출하면 인스턴스가 생성되지 않는다.

---

# 17.2.3 생성자 함수의 인스턴스 생성 과정

생성자 함수의 역할은 크게 두 가지다.

1. 인스턴스를 생성한다.
2. 생성된 인스턴스를 초기화한다.

```js
function Circle(radius) {
  this.radius = radius;

  this.getDiameter = function () {
    return 2 * this.radius;
  };
}

const circle1 = new Circle(5);
```

코드에는 인스턴스를 직접 생성하거나 반환하는 부분이 보이지 않는다.

하지만 자바스크립트 엔진은 `new`와 함께 생성자 함수를 호출하면 내부적으로 인스턴스를 생성하고 반환한다.

---

## 1단계. 인스턴스 생성과 this 바인딩

`new`와 함께 생성자 함수를 호출하면 먼저 빈 객체가 암묵적으로 생성된다.

이 빈 객체가 생성자 함수가 만들 인스턴스다.

그리고 이 인스턴스가 `this`에 바인딩된다.

```js
function Circle(radius) {
  console.log(this); // Circle {}

  this.radius = radius;
}
```

---

## 바인딩이란?

바인딩은 식별자와 값을 연결하는 과정이다.

예를 들어 변수 선언은 변수 이름과 메모리 공간을 연결하는 것이다.

`this` 바인딩은 `this`와 `this`가 가리킬 객체를 연결하는 것이다.

---

## 2단계. 인스턴스 초기화

생성자 함수 내부 코드가 실행되면서 `this`에 프로퍼티와 메서드가 추가된다.

```js
function Circle(radius) {
  this.radius = radius;

  this.getDiameter = function () {
    return 2 * this.radius;
  };
}
```

이 과정에서 생성자 함수로 전달받은 인수도 인스턴스 프로퍼티의 초기값으로 할당된다.

---

## 3단계. 인스턴스 반환

생성자 함수 내부 처리가 끝나면 완성된 인스턴스가 바인딩된 `this`가 암묵적으로 반환된다.

```js
function Circle(radius) {
  this.radius = radius;

  this.getDiameter = function () {
    return 2 * this.radius;
  };
}

const circle = new Circle(1);

console.log(circle); // Circle { radius: 1, getDiameter: f }
```

---

## 생성자 함수에서 return 사용 시 주의점

생성자 함수에서는 보통 `return` 문을 생략해야 한다.

### 객체를 명시적으로 반환하는 경우

```js
function Circle(radius) {
  this.radius = radius;

  this.getDiameter = function () {
    return 2 * this.radius;
  };

  return {};
}

const circle = new Circle(1);

console.log(circle); // {}
```

객체를 명시적으로 반환하면 암묵적으로 반환되어야 할 `this`가 무시되고, 명시적으로 반환한 객체가 반환된다.

---

### 원시값을 명시적으로 반환하는 경우

```js
function Circle(radius) {
  this.radius = radius;

  this.getDiameter = function () {
    return 2 * this.radius;
  };

  return 100;
}

const circle = new Circle(1);

console.log(circle); // Circle { radius: 1, getDiameter: f }
```

원시값을 반환하면 해당 반환값은 무시되고 `this`가 암묵적으로 반환된다.

---

## 정리

| 단계  | 설명                                         |
| ----- | -------------------------------------------- |
| 1단계 | 빈 객체가 생성되고 this에 바인딩된다         |
| 2단계 | this에 프로퍼티와 메서드를 추가해 초기화한다 |
| 3단계 | 완성된 this가 암묵적으로 반환된다            |

---

# 17.2.4 내부 메서드 [[Call]]과 [[Construct]]

함수는 객체다.

따라서 일반 객체처럼 프로퍼티와 메서드를 가질 수 있다.

```js
function foo() {}

foo.prop = 10;

foo.method = function () {
  console.log(this.prop);
};

foo.method(); // 10
```

하지만 함수는 일반 객체와 다르다.

일반 객체는 호출할 수 없지만 함수는 호출할 수 있다.

---

## 함수 객체의 내부 메서드

함수 객체는 함수로 동작하기 위해 내부적으로 특별한 메서드를 가진다.

| 내부 메서드     | 의미                                      |
| --------------- | ----------------------------------------- |
| `[[Call]]`      | 일반 함수로 호출될 때 실행                |
| `[[Construct]]` | `new`와 함께 생성자 함수로 호출될 때 실행 |

```js
function foo() {}

foo(); // [[Call]] 호출
new foo(); // [[Construct]] 호출
```

---

## callable, constructor, non-constructor

| 구분            | 설명                                           |
| --------------- | ---------------------------------------------- |
| callable        | 호출할 수 있는 객체, 즉 함수                   |
| constructor     | `new`와 함께 생성자 함수로 호출할 수 있는 함수 |
| non-constructor | `new`와 함께 호출할 수 없는 함수               |

모든 함수 객체는 호출할 수 있으므로 `callable`이다.

하지만 모든 함수 객체가 생성자 함수로 호출될 수 있는 것은 아니다.

---

## 핵심 정리

```md
모든 함수는 호출할 수 있다.
하지만 모든 함수가 new와 함께 생성자 함수로 호출될 수 있는 것은 아니다.
```

즉, 함수 객체는 다음 둘 중 하나다.

```md
callable + constructor
callable + non-constructor
```

---

# 17.2.5 constructor와 non-constructor의 구분

자바스크립트 엔진은 함수 정의 방식에 따라 함수를 `constructor`와 `non-constructor`로 구분한다.

---

## constructor

`constructor`는 `new`와 함께 호출할 수 있는 함수다.

| 구분        | 예시                          |
| ----------- | ----------------------------- |
| 함수 선언문 | `function foo() {}`           |
| 함수 표현식 | `const bar = function () {};` |
| 클래스      | `class Person {}`             |

```js
function foo() {}
const bar = function () {};

new foo();
new bar();
```

---

## non-constructor

`non-constructor`는 `new`와 함께 호출할 수 없는 함수다.

| 구분                 | 예시                      |
| -------------------- | ------------------------- |
| 화살표 함수          | `const arrow = () => {};` |
| ES6 메서드 축약 표현 | `const obj = { x() {} };` |

```js
const arrow = () => {};

new arrow(); // TypeError
```

```js
const obj = {
  x() {},
};

new obj.x(); // TypeError
```

---

## 주의할 점

객체의 프로퍼티 값으로 할당된 일반 함수는 일반적으로 메서드라고 부르지만, ECMAScript 사양에서는 ES6 메서드 축약 표현만 메서드로 인정한다.

```js
const baz = {
  x: function () {},
};

new baz.x(); // 가능
```

위의 `x`는 객체의 프로퍼티 값으로 들어간 함수지만, 함수 표현식으로 정의된 일반 함수이므로 `constructor`다.

---

## 정리

| 함수 정의 방식       | constructor 여부 |
| -------------------- | ---------------- |
| 함수 선언문          | constructor      |
| 함수 표현식          | constructor      |
| 클래스               | constructor      |
| 화살표 함수          | non-constructor  |
| ES6 메서드 축약 표현 | non-constructor  |

---

# 17.2.6 new 연산자

일반 함수와 생성자 함수는 특별한 문법적 차이가 없다.

함수를 `new`와 함께 호출하면 생성자 함수처럼 동작한다.

```js
function add(x, y) {
  return x + y;
}

const inst = new add();

console.log(inst); // {}
```

`add` 함수는 원래 생성자 함수로 만든 것이 아니다.

하지만 `new`와 함께 호출했기 때문에 빈 객체가 생성되어 반환된다.

---

## 객체를 반환하는 일반 함수를 new와 함께 호출한 경우

```js
function createUser(name, role) {
  return { name, role };
}

const inst = new createUser("Lee", "admin");

console.log(inst); // { name: "Lee", role: "admin" }
```

생성자 함수 내부에서 객체를 명시적으로 반환하면 그 객체가 반환된다.

---

## new 없이 생성자 함수를 호출한 경우

```js
function Circle(radius) {
  this.radius = radius;

  this.getDiameter = function () {
    return 2 * this.radius;
  };
}

const circle = Circle(5);

console.log(circle); // undefined
```

`new` 없이 호출하면 `Circle`은 생성자 함수가 아니라 일반 함수로 실행된다.

브라우저 환경에서 일반 함수 내부의 `this`는 전역 객체 `window`를 가리킨다.

```js
console.log(radius); // 5
console.log(getDiameter()); // 10
```

즉, `radius`와 `getDiameter`가 의도치 않게 전역 객체의 프로퍼티와 메서드가 될 수 있다.

---

## 핵심 정리

| 호출 방식       | 내부 동작                              |
| --------------- | -------------------------------------- |
| `Circle(5)`     | 일반 함수 호출, `[[Call]]` 실행        |
| `new Circle(5)` | 생성자 함수 호출, `[[Construct]]` 실행 |

---

# 17.2.7 new.target

`new.target`은 생성자 함수가 `new`와 함께 호출되었는지 확인할 수 있는 문법이다.

---

## new.target의 동작

| 호출 방식      | new.target 값  |
| -------------- | -------------- |
| `new Circle()` | 함수 자기 자신 |
| `Circle()`     | `undefined`    |

```js
function Circle(radius) {
  if (!new.target) {
    return new Circle(radius);
  }

  this.radius = radius;

  this.getDiameter = function () {
    return 2 * this.radius;
  };
}

const circle = Circle(5);

console.log(circle.getDiameter()); // 10
```

위 코드에서는 `new` 없이 `Circle(5)`를 호출해도 내부에서 다시 `new Circle(5)`로 호출해 인스턴스를 생성한다.

---

## new.target을 사용하는 이유

생성자 함수는 원래 `new`와 함께 호출해야 한다.

하지만 실수로 `new`를 빼먹을 수 있다.

```js
const circle = Circle(5);
```

이런 실수를 방지하기 위해 `new.target`을 사용할 수 있다.

---

## 스코프 세이프 생성자 패턴

`new.target`을 사용할 수 없는 환경에서는 `instanceof`를 이용할 수 있다.

```js
function Circle(radius) {
  if (!(this instanceof Circle)) {
    return new Circle(radius);
  }

  this.radius = radius;

  this.getDiameter = function () {
    return 2 * this.radius;
  };
}

const circle = Circle(5);

console.log(circle.getDiameter()); // 10
```

`new`와 함께 호출된 경우 `this`는 `Circle`의 인스턴스다.

반대로 `new` 없이 호출되면 `this`는 인스턴스가 아니므로 다시 `new Circle(radius)`를 호출한다.

---

# 빌트인 생성자 함수와 new

대부분의 빌트인 생성자 함수는 `new`와 함께 호출되었는지에 따라 적절한 값을 반환한다.

---

## Object와 Function

`Object`와 `Function`은 `new` 없이 호출해도 `new`와 함께 호출한 것처럼 동작한다.

```js
let obj = new Object();
console.log(obj); // {}

obj = Object();
console.log(obj); // {}
```

```js
let f = new Function("x", "return x ** x");
console.log(f);

f = Function("x", "return x ** x");
console.log(f);
```

---

## String, Number, Boolean

`String`, `Number`, `Boolean`은 `new`와 함께 호출하면 객체를 반환한다.

```js
const strObj = new String("Lee");
console.log(typeof strObj); // object
```

하지만 `new` 없이 호출하면 원시값을 반환한다.

```js
const str = String(123);
console.log(str, typeof str); // 123 string

const num = Number("123");
console.log(num, typeof num); // 123 number

const bool = Boolean("true");
console.log(bool, typeof bool); // true boolean
```

이 특징을 이용해 타입 변환을 할 수 있다.

# 최종 핵심 요약

## 객체 리터럴 방식

```md
객체 하나를 간단히 만들 때는 좋다.
하지만 같은 구조의 객체를 여러 개 만들 때는 비효율적이다.
```

---

## 생성자 함수 방식

```md
동일한 프로퍼티 구조를 가진 객체를 여러 개 만들 때 유용하다.
new와 함께 호출하면 인스턴스를 생성한다.
```

---

## 생성자 함수의 내부 과정

```md
1. 빈 객체 생성
2. this에 빈 객체 바인딩
3. this에 프로퍼티와 메서드 추가
4. 완성된 this 반환
```

---

## this 바인딩

```md
일반 함수 호출 → 전역 객체
메서드 호출 → 메서드를 호출한 객체
생성자 함수 호출 → 생성될 인스턴스
```

---

## constructor와 non-constructor

```md
constructor → new로 호출 가능
non-constructor → new로 호출 불가능
```

---
