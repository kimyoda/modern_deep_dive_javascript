# 24.4 클로저 활용

- **상태를 외부에서 직접 변경하지 못하도록 숨기면서, 특정 함수만 상태를 변경하고 유지하도록 한다.**

## 전역 변수 → 지역 변수 → 클로저

**예제 24-09~24-11**

> 아래 코드 블록은 동일한 `increase` 이름을 사용하므로 **각 예제를 독립적으로 실행**한다.


```js
// [24-09] 전역 변수 사용 - 누구나 num을 바꿀 수 있다 (암묵적 결합).
let num = 0;

const increase = function () {
  return ++num;
};

console.log(increase()); // 1
console.log(increase()); // 2
console.log(increase()); // 3
```

```js
// [24-10] 지역 변수로 은닉 - 호출마다 0으로 초기화되어 상태 유지 불가
const increase = function () {
  let num = 0;
  return ++num;
};

console.log(increase()); // 1
console.log(increase()); // 1
console.log(increase()); // 1
```

```js
// [24-11] 클로저 사용 - 은닉 + 상태 유지
const increase = (function () {
  let num = 0;

  return function () {
    return ++num;
  };
})();

console.log(increase()); // 1
console.log(increase()); // 2
console.log(increase()); // 3
```

## 과정 비교

| 예제  | 방식          | 숨김 | 유지 | 문제점                   |
| ------ | -------------- | ----- | ----- | ------------------------- |
| 24-09 | 전역 변수     | X    | O    | 누구나 `num`을 변경 가능 |
| 24-10 | 지역 변수     | O    | X    | 호출마다 재선언, 초기화  |
| 24-11 | 클로저 + IIFE | O    | O    | (해결)                   |

## 24-11의 렉시컬 환경

| 시점                  | 생성되는지               | num 초기화               |
| ---------------------- | ------------------------- | ------------------------- |
| IIFE 호출             | num 바인딩과 반환 함수   | 0으로 한 번 초기화       |
| increase 첫 호출      | 반환 함수의 호출 환경    | 초기화하지 않고 1로 변경 |
| increase 두 번째 호출 | 반환 함수의 새 호출 환경 | 같은 바인딩을 2로 변경   |

상태를 유지하는 이유는 반환 함수가 같은 IIFE의 `num` 바인딩을 계속 참조하기 때문이다.

## 증가 및 감소 기능을 가진 객체 반환

**예제 24-12**

```js
const counter = (function () {
  // 카운트 상태 변수
  let num = 0;

  // 클로저인 메서드를 갖는 객체를 반환
  // 객체 리터럴은 스코프를 만들지 않음
  // 따라서 아래 메서드들의 상위 스코프는 즉시 실행 함수의 렉시컬 환경
  return {
    // num: 0, // 프로퍼티는 public이므로 은닉되지 않음
    increase() {
      return ++num;
    },
    decrease() {
      return num > 0 ? --num : 0;
    },
  };
})();

console.log(counter.increase()); // 1
console.log(counter.increase()); // 2

console.log(counter.decrease()); // 1
console.log(counter.decrease()); // 0
```

## 생성자 함수 버전

**예제 24-13**

> 예제 24-12와 24-13은 각각 독립적인 코드 블록으로 실행한다.


```js
const Counter = (function () {
  // 1 카운트 상태 변수
  let num = 0;

  function Counter() {
    // this.num = 0; // 2. 프로퍼티는 public하므로 은닉되지 않음
  }

  Counter.prototype.increase = function () {
    return ++num;
  };

  Counter.prototype.decrease = function () {
    return num > 0 ? --num : 0;
  };

  return Counter;
})();

const counter = new Counter();

console.log(counter.increase()); // 1
console.log(counter.increase()); // 2

console.log(counter.decrease()); // 1
console.log(counter.decrease()); // 0
```

## `this.num`과 `let num`의 차이

| 구분           | 위치              | 외부 접근            | 비고                              |
| --------------- | ------------------ | --------------------- | ---------------------------------- |
| `this.num` (2) | 인스턴스 프로퍼티 | O (public)           | 의도치 않은 변경 가능             |
| `let num` (1)  | IIFE 지역 변수    | X (private처럼 동작) | `increase`/`decrease`만 변경 가능 |

## 24-13은 인스턴스별 카운터가 아님
IIFE는 한 번만 실행되어 `num`도 한 개만 만들어진다. 두 인스턴스의 프로토타입 메서드는 같은 바인딩을 읽고 변경한다.

아래 코드는 예제 24-13의 `Counter` 선언에 이어 실행한다.

```js
const counterA = new Counter();
const counterB = new Counter();

console.log(counterA.increase()); // 1
console.log(counterB.increase()); // 2
console.log(counterA.increase()); // 3
```

위 출력은 `num`이 0인 상태를 기준으로 한다. 예제 24-13의 증가·감소 호출을 모두 실행한 뒤에도 `num`이 0이므로 같은 결과가 나온다.

독립적인 상태가 필요하면 호출할 때마다 지역 변수를 만드는 팩터리 함수를 사용할 수 있다.

```js
function createCounter() {
  let num = 0;

  return {
    increase() {
      return ++num;
    },
    decrease() {
      return num > 0 ? --num : 0;
    },
    getValue() {
      return num;
    },
  };
}

const counterA = createCounter();
const counterB = createCounter();

console.log(counterA.increase()); // 1
console.log(counterA.increase()); // 2
console.log(counterB.increase()); // 1
console.log(counterA.getValue()); // 2
```

| 생성 방식     | 상태를 선언한 위치 | 범위                                  |
| -------------- | ------------------- | -------------------------------------- |
| 24-12         | 한 번 실행한 IIFE  | 반환 객체의 increase, decrease가 공유 |
| 24-13         | 한 번 실행한 IIFE  | 모든 Counter 인스턴스가 공유          |
| createCounter | 팩터리 호출 내부   | 같은 호출에서 만든 메서드끼리만 공유  |

## 고차 함수와 클로저(함수형 프로그래밍)

**예제 24-14**

```js
// 함수를 인수로 전달받고 함수를 반환하는 고차 함수
// 이 함수가 반환하는 함수는 카운트 상태를 유지하기 위한 자유 변수 counter를 기억하는 클로저
function makeCounter(predicate) {
  // 카운트 상태를 유지하기 위한 자유 변수
  let counter = 0;

  // 클로저를 반환
  return function () {
    // 인수로 전달받은 보조 함수에 상태 변경을 위임한다
    counter = predicate(counter);
    return counter;
  };
}

// 보조 함수
function increase(n) {
  return ++n;
}

// 보조 함수
function decrease(n) {
  return --n;
}

// 함수로 함수를 생성
// makeCounter 함수는 보조 함수를 인수로 전달받아 함수를 반환한다
const increaser = makeCounter(increase); // 1
console.log(increaser()); // 1
console.log(increaser()); // 2

// increaser 함수와는 별개의 독립된 렉시컬 환경을 갖기 때문에 카운터 상태가 연동하지 않는다
const decreaser = makeCounter(decrease); // 2
console.log(decreaser()); // -1
console.log(decreaser()); // -2
```

## `makeCounter`를 두 번 호출

| 변수      | 함수 생성 호출        | counter 바인딩         | 두 번 호출 |
| ---------- | ---------------------- | ----------------------- | ----------- |
| increaser | makeCounter(increase) | 첫 번째 호출의 counter | 1, 2       |
| decreaser | makeCounter(decrease) | 두 번째 호출의 counter | -1, -2     |

> `makeCounter`를 **호출할 때마다 새 렉시컬 환경**이 만들어지므로 두 카운터는 `counter`를 공유하지 않음

## 렉시컬 환경을 공유하는 카운터

**예제 24-15**

```js
// 함수를 반환하는 고차 함수
// 함수가 반환하는 함수는 카운트 상태를 유지하기 위한 자유 변수 counter를 기억하는 클로저다
const counter = (function () {
  // 카운트 상태를 유지하기 위한 자유 변수
  let counter = 0;

  // 함수를 인수로 전달받는 클로저를 반환
  return function (predicate) {
    // 인수로 전달받은 보조 함수에 상태 변경을 위임한다
    counter = predicate(counter);
    return counter;
  };
})();

// 보조 함수
function increase(n) {
  return ++n;
}

// 보조 함수
function decrease(n) {
  return --n;
}

// 보조 함수를 전달하여 호출
console.log(counter(increase)); // 1
console.log(counter(increase)); // 2

// 자유 변수를 공유
console.log(counter(decrease)); // 1
console.log(counter(decrease)); // 0
```

## 24-14와 24-15 비교

| 구분             | 24-14                       | 24-15                |
| ----------------- | ---------------------------- | --------------------- |
| 클로저 생성 횟수 | `makeCounter` 호출할 때마다 | IIFE 실행 시 **1번** |
| `counter` 변수   | 클로저마다 독립             | **모든 호출이 공유** |
| 증가/감소 연동   | X                           | O                    |
