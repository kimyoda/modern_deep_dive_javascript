## 44.1 REST API

> **URI로 대상을 식별, HTTP 메서드로 무엇을 요청하는 지 표현. 응답에서 상태 코드와 본문을 구분해 처리한다**

## 44.1 REST API 구성

REST는 로이 빌딩이 2000년 박사 논문에 정리한 웹 아키텍처 스타일. HTTP 기반 API를 설계할 때 아래 세가지를 구분하면 요청을 읽기 쉽다

| 구성 요소 | 뜻                                     | API 예시                                 |
| --------- | -------------------------------------- | ---------------------------------------- |
| 자원      | 조회하거나 변경할 대상                 | `/todos`, `/todos/1`                     |
| 행위      | 자원에 무엇을 요청하는 지              | `GET`, `POST`, `PUT`, `PATCH`, `DELETE`  |
| 표현      | 네트워크로 주고받은 자원의 데이터 표현 | `{"content": "HTML", "completed": true}` |

REST 구성 요소 표. JSON은 표현 형식 중 하나.

REST의 범위는 CRUD 경로 규칙보다 넓음. 필딩 제약에 클라이언트·서버 분리, 무상태, 캐시, 계층화, 균일한 인터페이스, 선택적인 코드 온 디맨드가 포함.
균일한 인터페이스에는 응답의 링크 등으로 다음 동작을 안내하는 하이퍼미디어도 포함. **무상태는 서버가 데이터를 저장할 수 없다는 뜻이 아니다**
각 요청을 이해하는 데 필요한 정보가 그 요청에 들어 있어야 한다는 뜻
