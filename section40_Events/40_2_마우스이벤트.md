## 40.2 이벤트 타입

이벤트 타입은 click·input 처럼 사건의 종류를 나타내는 문자열. addEventListener에 on을 붙이지 않음

### 40.2.1 마우스 이벤트

| 타입                  | 상황                           | 다른점                             |
| --------------------- | ------------------------------ | ---------------------------------- |
| click                 | 클릭·키보드 등으로 요소 활성화 | 마우스 전용 입력으로 생각하지 않음 |
| dbclick               | 더블 클릭                      | 일반적으로 click들이 먼저 발생     |
| mousedown             | 마우스 버튼 누름               | 드래그 시작 등에 사용              |
| mouseup               | 마우스 버튼 놓음               | 드래그 시작 등에 사용              |
| mousemove             | 포인터 이동                    | 빈번하게 발생할 수 있음            |
| mouseenter·mouseleave | 요소 영역 진입·이탈            | 버블링하지 않음                    |
| mouseover·mouseout    | 요소 위로 진입·이탈            | 버블링하며 자손 경계 이동도 고려   |

새로운 포인터 상호작용에 마우스·펜·터치를 함께 다루는 pointerdown·pointermove·pointerup 등도 사용할 수 있음

### 40.2.2 키보드 이벤트

| 타입     | 의미                                           |
| -------- | ---------------------------------------------- |
| keydown  | 키를 누를 때, 누르고 있으면 반복될 수 있음     |
| keyup    | 키를 놓을 때                                   |
| keypress | 과거 문자 입력 이벤트. 사용하지 않는 편이 좋음 |

단축키·Enter 판정에 keydown·keyup, 실제 입력값 변화에 input을 사용. 붙여넣기나 음성 입력처럼 키보드 없이 값이 바뀌는 경우도 있음

### 40.2.3 포커스 이벤트

| 타입     | 의미          | 버블링 |
| -------- | ------------- | ------ |
| focus    | 포커스를 얻음 | 없음   |
| blur     | 포커스를 잃음 | 없음   |
| focusin  | 포커스를 얻음 | 있음   |
| focusout | 포커스를 잃음 | 있음   |

부모에서 자식의 포커스를 관찰할 때 focus의 캡처 리소스나 focusin 등을 사용할 수 있음. "버블링하지 않는다"와 "상위에서 절대 관찰할 수 없다"는 다른말

### 40.2.4 폼 이벤트

| 타입   | 의미      |
| ------ | --------- |
| submit | 폼 제출   |
| reset  | 폼 초기화 |

submit은 버튼 클릭뿐 아니라 Enter나 requestSubmit 등으로 시작될 수 있음. 제출 처리를 버튼의 click에만 등록하기보다 form의 submit에 등록하면 여러 제출 경로를 다를 수 있음

### 40.2.5 값 변경 이벤트

| 타입             | 의미                                                     |
| ---------------- | -------------------------------------------------------- |
| input            | 사용자 조작으로 입력값이 바뀔 때                         |
| change           | 값 변경을 확정할 때. 확정 시점은 컨트롤 종류에 따라 다름 |
| readystatechange | document.readyState가 바뀔 때                            |

텍스트 입력의 change는 보통 값을 바꾼 뒤 포커스를 잃을 때 발생. 체크박스·select는 선택을 변경할 때 발생할 수 있어 모든 change가 blur 때만 발생한다고 외우지 않음

JavaScript에 input.value를 대입하는 것만으로 input·change가 자동 발생하지 않음

### 40.2.6 DOM 준비 이벤트

DOMContentLoaded는 HTML 파싱과 DOM 준비가 완료된 시점을 관찰. DOM 변경을 매번 알려 주는 이벤트는 아님.
DOM 변화를 관찰하면 MutationObserver를 검토

```js
function setup() {
  console.log("DOM 사용 준비 완료");
}

if (document.readyState === "loading") {
  document.addEventListener("DOMContentLoaded", setup, { once: true });
} else {
  setup();
}
```

스크립트가 늦게 실행되면 DOMContentLoaded가 이미 끝났을 수 있음. readyState를 확인해 아직 로딩 중이면 기다리중이고, 준비되었으면 즉시 초기화한다

### 40.2.7 뷰 이벤트

| 타입   | 의미                             |
| ------ | -------------------------------- |
| resize | window 뷰포트 크기 변화          |
| scroll | 문서나 스크롤 가능한 요소 스크롤 |

일반 요소 크기 변화를 관찰하려면 window.resize만으로 부족하고 ResizeObserver 같은 API를 사용

### 40.2.8 리소스 이벤트

| 타입   | 의미                                             |
| ------ | ------------------------------------------------ |
| load   | 대상 리소스 또는 문서의 로드 완료                |
| error  | 해당 리소스 등 오류                              |
| abort  | 해당 로드 작업의 중단                            |
| unload | 과거 페이지 종료 관찰에 사용. 현재는 의존을 피함 |

DOMContentLoaded는 모든 이미지 로드까지 기다리지 않음. window.load는 문서와 관련 리소스 로드 시점이며, 지연 로드 등 모든 후속 작업의 완료를 뜻하지 않음. unload는 실행 보장이 없고 권장되지 않음
