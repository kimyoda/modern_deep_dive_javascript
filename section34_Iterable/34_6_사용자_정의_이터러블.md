## 34.6 사용자 정의 이터러블

### 34.6.1 사용자 정의 이터러블 구현

일반적인 피보나치 수열의 시작값 정의와 구분

```js
const fibonacci = {
  [Symbol.iterator]() {
    let [previous, current] = [0, 1];
    return {
      next() {
        [previous, current] = [current, previous + current];
        return current < 10
          ? { value: current, done: false }
          : { value: undefined, done: true };
      },
    };
  },
};

console.log([...fibonacci]); // [1, 2, 3, 5, 8]
const [first, second, ...rest] = fibonacci;
console.log(first, second, rest); // 1 2 [3, 5, 8]
```

### 34.6.2 이터러블을 생성하는 함수

상한을 외부에서 전달, 각 순회의 상태는 Symbol.iterator 호출

```js
function createFibonacci(max) {
  return {
    [Symbol.iterator]() {
      let [previous, current] = [0, 1];
      return {
        next() {
          [previous, current] = [current, previous + current];
          return current < max
            ? { value: current, done: false }
            : { value: undefined, done: true };
        },
      };
    },
  };
}

const iterable = createFibonacci(10);
console.log([...iterable]); // [1, 2, 3, 5, 8]
console.log([...iterable]); // [1, 2, 3, 5, 8]
console.log([...createFibonacci(5)]); // [1, 2, 3]
```

상태를 함수의 바깥쪽에 두고 모든 이터레이터가 공유하면 재순회·중첩 순회에 위치를 공유할 수 있음

### 34.6.3 이터러블이며 이터레이터인 객체

Symbol.iterator가 자기 자신을 반환하도록 만들면 두 규약을 모두 만족

```js
function createFibonacciIterator(max) {
  let [previous, current] = [0, 1];
  return {
    [Symbol.iterator]() {
      return this;
    },
    next() {
      [previous, current] = [current, previous + current];
      return current < max
        ? { value: current, done: false }
        : { value: undefined, done: true };
    },
  };
}

const iterator = createFibonacciIterator(10);
console.log(iterator[Symbol.iterator]() === iterator); // true
console.log(iterator.next()); // { value: 1, done: false}
console.log([...iterator]); // [2, 3, 5, 8]
console.log([...iterator]); // []
```

같은 객체는 진행 상태를 공유. 처음부터 읽으면 새로운 이터레이터를 만듬

### 34.6.4 무한 이터러블과 지연 평가

```js
function createInfiniteFibonacci() {
  let [previous, current] = [0n, 1n];
  return {
    [Symbol.iterator]() {
      return this;
    },
    next() {
      [previous, current] = [current, previous + current];
      return { value: current, done: false };
    },
  };
}

const values = [];
for (const number of createInfiniteFibonacci()) {
  if (number > 10000n) {
    break;
  }
  values.push(number.toString());
}
console.log(values.slice(-2)); // ['4181', '6765']

const [a, b, c] = createInfiniteFibonacci();
console.log(a, b, c); // 1n 2n 3n
```

큰 정수의 정밀도를 유지하도록 BigInt를 사용. next가 호출될 때 다음 항을 계산하는 것이 지연 평가

**무한 이터러블에 배열 Spread·Array.from·Rest 요소를 적용하면 끝까지 소비하려 한다**

### 순회 조기 종료, return

```js
const events = [];
const iterable = {
  [Symbol.iterator]() {
    let value = 0;
    return {
      next() {
        return { value: ++value, done: false };
      },
      return() {
        events.push("정리");
        return { done: true };
      },
    };
  },
};

for (const value of iterable) {
  events.push(value);
  break;
}
console.log(events); // [1, '정리']
```

for...of의 break나 일부 값만 받는 배열 구조 분해는 필요하면 이터레이터의 return을 호출한다. 모든 종류 종료·예외가 무조건 return을 호출하는 것은 아님

## 질문, 답변

### 1. 이터러블 조건

- Symbol.iterator 메서드로 올바른 이터레이터를 반환

### 2. 이터레이터의 조건

- next 메서드가 결과 객체를 반환

### 3. value와 done 역할

- 현재 값과 순회 완료 여부

### 4. done이 true인 결과의 value도 for...of에 전달되는 지

- 아님. 종료 결과의 값은 본문에 전달되지 않음

### 5. 메서드 존재 검사만으로 올바른 이터러블을 보장

- 아님. 반환 객체와 next 동작도 맞아야 한다

### 6. 일반 객체에 객체 Spread가 가능한 이유

- 이터러블 순회가 아니라 자체 열거 가능 프로퍼티를 복사하기 때문

### 7. for...in과 for...of의 차이

- 문자열 프로퍼티 키 열거와 이터레이터의 값 순회

### 8. 모든 유사 배열이 이터러블

- 아님. 인덱스·length와 Symbol.iterator는 별개 조건

### 9. Array.from 무엇을 받는 지

- key와 value를 담은 배열

### 10. Map을 기본 순회하면 무엇이 나오는 지

- 각 Symbol.iterator 호출 안에 두어 이터레이터마다 분리

### 11. 재순회 가능한 객체의 상태는 어디에 두는 지

- 각 Symbol.iterator 호출 안에 두어 이터레이터마다 분리

### 12. Symbol.iterator가 this를 반환

- 자신의 next를 사용하는 이터러블 이터레이터가 된다

### 13. 이터레이터를 두 번 펼치면 항상 같은 결과

- 아님. 이미 진행하거나 소진한 상태를 이어서 사용
