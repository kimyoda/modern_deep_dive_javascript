# 21장 빌트인 객체

## 학습 목표 및 체크 사항

- 표준 빌트인, 호스트, 사용자 정의 객체를 구분
- 원시 값의 메서드 사용을 래퍼 동작으로 설명하되 **변수 자체가 객체로 재할당된다고 이해하지 않는다**
- `globalThis`와 최상위 `this`가 실행 환경에 따라 다름을 확인
- 숫자로 변환하는 전역 함수 `isNaN`, `isFinite`와 자동으로 타입을 변환하지 않는 `Number` 정적 메서드를 비교한다
- `eval`의 지역 선언, strict 규칙과 암묵적 전역을 구분

| 분류        | 기준                | 예                                        |
| ----------- | ------------------- | ----------------------------------------- |
| 표준 빌트인 | ECMAScript에서 정의 | Object, Array, Map, Promise, JSON         |
| 호스트 API  | 실행 환경이 제공    | 브라우저 DOM, Node.js의 process, 파일 API |
| 사용자 정의 | 앱 정의             | Player 객체, 직접 만든 서비스 객체        |

일부 API는 여러 실행 환경에 존재한다. 예를 들어 `fetch`를 브라우저 전용 API로 단정하지 않는다.

> **실행 환경 주의:** `window`를 사용하는 예제와 암묵적 전역 예제는 브라우저의 일반 `<script>` 기준이다. ES 모듈에는 strict mode가 자동 적용되며, Node.js 파일의 최상위 선언은 브라우저 일반 스크립트의 전역 선언과 다르다.

## 21.1 자바스크립트 객체 분류

자바스크립트 객체는 크게 다음 세 종류로 분류할 수 있다.

### 표준 빌트인 객체

표준 빌트인 객체는 ECMAScript 사양에 정의된 객체다. 앱 전역에서 사용하는 공통 기능을 제공하며, ECMAScript를 지원하는 실행 환경에서 사용할 수 있다. `Object`, `Array`, `Promise` 등은 전역 객체의 프로퍼티로 제공되므로 별도로 선언하지 않고 참조할 수 있다.

### 호스트 객체

ECMAScript 사양 자체가 아니라 자바스크립트 실행 환경이 추가로 제공하는 객체를 말한다.

브라우저 환경은 DOM, BOM, Canvas, `XMLHttpRequest`, `fetch`, `requestAnimationFrame`, SVG, Web Storage, Web Components, Web Workers 등 클라이언트 측 Web API를 제공한다. Node.js 환경은 `process`, 파일 시스템 모듈 등 Node.js 고유 API를 제공한다. 일부 Web API는 Node.js에서도 사용할 수 있다.

### 사용자 정의 객체

개발자가 애플리케이션 요구 사항에 맞춰 직접 정의한 객체다. 예를 들어 `Player` 객체나 직접 작성한 서비스 객체가 있다.
