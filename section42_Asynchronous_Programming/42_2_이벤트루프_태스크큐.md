## 42.2 이벤트 루프와 태스크 큐

### 42.2.1 브라우저 구성과 역할

```mermaid
flowchart TD
  subgrapg Engine["JavaScript 엔진"]
    S["콜 스택"]
    H["힙: 객체 등이 저장되는 공간"]
    S -.->|"객체 참조"| H
  end
  S -->|"타이머 예약"| W["호스트 API: 타이머, DOM, 네트워크"]
  W -->|"타이머 대기 조건 충족"| Q["실행 가능한 타이머 태스크"]
  Q -->|"실행할 작업 선택"| L["브라우저 이벤트 루프"]
  L -->|"태스크를 실행하면 콜백이 스택에 올라감"| S
```

| 구성        | 하는 일                                                                               |
| ----------- | ------------------------------------------------------------------------------------- |
| 콜 스택     | 현재 실행 중인 코드와 함수의 호출·복귀를 관리                                         |
| 힙          | 객체 등이 저장되는 메모리 공간. 실행 대기열은 아님                                    |
| 호스트 API  | 브라우저가 제공하는 기능. 타이머를 등록하고 대기 조건이 충족되면 실행할 작업을 준비   |
| 태스크 큐   | 타이머처럼 나중에 처리할 태스크를 관리. 브라우저에 태스크 큐가 하나 이상 있을 수 있음 |
| 이벤트 루프 | 실행할 태스크를 고르고 마이크로태스크 처리와 렌더링 기회 등을 조율                    |

이벤트 루프가 함수 객체를 직접 스택에 옮긴다기보다, **태스크가 실행되며 콜백이 호출되고** 실행 컨텍스트가 스택에 들어간다고 이해하면 된다. 태스크가 항상 하나의 FIFO 큐에 처리된다고 가정하지 않음

### 42.2.2 setTimeout 0ms 직접 호출 순서

```js
function foo() {
  console.log("foo");
}
function bar() {
  console.log("bar");
}

setTimeout(foo, 0);
bar();
console.log("전역 코드 끝");

// bar -> 전역 코드 끝 -> foo
```

1. 현재 코드가 실행, `setTimeout`은 호스트에 foo 실행을 예약한 뒤 반환한다
2. 바로 이어진 `bar()`가 콜 스택에 실행되고 반환
3. `전역 코드 끝`이 출력되고 현재 코드 실행이 종료
4. 대기 조건을 충족한 타이머 태스크가 이벤트 루프에 선택되면 foo가 실행된다

0ms를 지정해도 foo가 현재 코드의 중간에 끼어들지 않음. 스택이 비는 것은 중요하나, 곧바로 타이머가 실행된다는 뜻은 아님.

### 42.2.3 태스크와 마이크로태스크

| 분류           | 예                                                                    |
| -------------- | --------------------------------------------------------------------- |
| 태스크         | 타이머 콜백을 호출하는 작업, 브라우저가 작업으로 전달하는 사용자 입력 |
| 마이크로태스크 | `queueMicrotask`에 넘긴 함수, Promise의 `then` 후속 처리              |

브라우저는 태스크 실행 이후 등의 시점에 마이크로태스크 체크포인트를 수행. 아래처럼 **같은 코드에서 이미 등록한 Promise 후속 처리**는 다음 타이머 태스크보다 먼저 실행.

```js
console.log("A");

setTimeout(() => console.log("B: 타이머"), 0);
Promise.resolve().then(() => console.log("C: Promise"));
queueMicrotask(() => console.log("D: queueMicrotask"));

console.log("E");

// A -> E -> C: Promise -> D: queueMicrotask -> B: 타이머
```

| 순서 | 내용 | 이유                                   |
| ---: | ---- | -------------------------------------- |
|    1 | A, E | 현재 코드가 동기적으로 실행            |
|    2 | C    | 이미 이행된 Promise에 등록한 후속 처리 |
|    3 | D    | C 다음에 마이크로태스크 큐에 등록      |
|    4 | B    | 이후 타이머 태스크가 선택되어 실행     |

아직 네트워크 응답을 기다리는 Promise의 `then`이 이미 실행 가능한 타이머보다 무조건 먼저 실행되는 것은 아님

마이크로태스크가 계속 추가되면 다음 태스크나 화면 갱신도 밀릴 수 있음

### 42.2.4 싱글 스레드와 실행 환경

하나의 JavaScript 실행 단위에 코드는 콜 스택을 따라 실행. 브라우저 전체가 하나의 스레드만 사용한다는 뜻은 아님. 네트워크·렌더링·타이머 등 여러 기능을 제공, Web Worker는 메인 스레드와 별도의 실행 환경을 가짐

Node.js도 비동기 입출력과 타이머를 처리, 브라우저와 이벤트 루프 구성이 동일하지 않음. `setImmedite`, `process.nextTick` 타이머 상대 순서를 단정하지 않음

## 질문, 답변

### 1. foo, bar를 차례로 직접 호출하면 둘이 동시에 스택이 있는지

- 아님. foo가 반환한 뒤 bar가 호출

### 2. 동기 대기 루프가 입력 처리를 늦추는 이유

- 메인 스레드가 루프 실행에 점유되기 때문

### 3. 타이머 대기와 콜백 실행은 누가 담당하는지

- 대기·스케줄링은 호스트, 콜백 본문 실행은 JavaScript 엔진이 담당

### 4. 스택이 비면 항상 가장 먼저 등록한 태스크가 실행되는 지

- 아님. 큐 선택, 실행 가능 여부, 마이크로태스크 처리 등을 고려

### 5. `await`는 브라우저 전체를 멈추는 지

- 아님. 해당 async 함수가 결과를 받은 뒤 이어서 실행

### 6. `setTimeout(foo, 0); bar();`에 무엇이 먼저 실행되는 지

- 직접 호출한 bar가 먼저

### 7. 이미 이행된 Promise 후속 처리와 0ms xkdlaj wnd andjtdl ajswjdlswl

- 둘을 같은 코드에 예약한 위 예제에서 마이크로태스크가 먼저

### 8 `Promise.all`에 한 요청이 실패하면 나머지도 취소인지

- 아님. 필요하면 별도로 취소
