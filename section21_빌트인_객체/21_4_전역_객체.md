## 21.4 전역 객체

전역 객체는 코드가 실행되기 전에 자바스크립트 엔진이 생성하는 특수한 객체다.
전역 객체를 가리키는 식별자는 실행 환경에 따라 다르다. 브라우저의 일반 스크립트에서는 `window`, `self`, `frames`, 최상위 `this`가 같은 전역 객체를 가리킨다. Node.js에서는 `global`을 사용한다. ES 모듈이나 Node.js 파일에서 최상위 `this`는 전역 객체가 아닐 수 있다.

**참고: `globalThis`**

ES11에서 도입된 `globalThis`는 브라우저와 Node.js 등 다양한 환경에서 전역 객체에 접근하기 위한 표준 식별자다.

**예제 21-08**

```js
// 브라우저 일반 스크립트 환경 (ES 모듈 제외)
globalThis === this; // true
globalThis === window; // true
globalThis === self; // true
globalThis === frames; // true
```

```js
// Node.js 환경
globalThis === global; // true
// CommonJS 파일 최상위 this는 module.exports, ES 모듈 최상위 this는 undefined다
// 따라서 Node.js 파일에 globalThis === this를 true로 일반화할 수 없다
```

전역 객체는 표준 빌트인 객체와 환경에 따른 호스트 API를 제공한다. 브라우저 일반 스크립트에서는 `var`로 선언한 전역 변수와 전역 함수도 전역 객체의 프로퍼티가 된다.
전역 객체는 전역 API를 제공하는 객체이며, 모든 객체의 프로토타입 체인에서 최상위 객체라는 의미는 아니다.

- 전역 객체를 생성하는 별도의 공개 생성자 함수는 제공되지 않는다.
- 일부 전역 프로퍼티는 `window`(또는 `globalThis`)를 생략하고 이름만으로 참조할 수 있다.

**예제 21-09**

```js
// 문자열 'F'를 16진수로 해석하여 10진수로 변환하여 반환한다
window.parseInt("F", 16); // -> 15
// window.parseInt는 parseInt로 호출할 수 있음
parseInt("F", 16); // 15
```

- 전역 객체는 `Object`, `String`, `Number` 등 표준 빌트인 객체를 프로퍼티로 제공한다.
- 실행 환경에 따라 추가 프로퍼티와 메서드를 가진다. 브라우저는 Web API를, Node.js는 Node.js 고유의 API를 제공한다.
- 브라우저 일반 스크립트에서는 `var`로 선언한 전역 변수, 전역 함수, 비엄격 모드의 암묵적 전역이 전역 객체의 프로퍼티가 될 수 있다.

**예제 21-10**

```js
// var 키워드로 선언한 전역 변수
var foo = 1;
console.log(window.foo); // 1

// 선언하지 않은 식별자에 대입하면 암묵적 전역이 생길 수 있다. bar는 전역 선언 변수가 아니라 전역 객체의 프로퍼티다
bar = 2; // window.bar = 2
console.log(window.bar); // 2

// 전역 함수
function baz() {
  return 3;
}
console.log(window.baz()); // 3
```

- `let`이나 `const`로 선언한 전역 바인딩은 전역 객체의 프로퍼티가 아니다. 대신 전역 렉시컬 환경의 선언적 환경 레코드에 저장된다.

**예제 21-11**

```js
let foo = 123;
console.log(window.foo); // undefined
```

> 예제 21-10과 21-11은 `foo` 선언이 충돌하지 않도록 각각 별도의 일반 스크립트에서 실행하는 예제다.

- 같은 브라우저 창의 일반 스크립트들은 해당 창의 전역 객체 `window`를 공유한다. 다른 창이나 iframe은 별도의 전역 객체를 가질 수 있다.

### 21.4.1 빌트인 전역 프로퍼티

#### Infinity

**예제 21-12**

```js
// 전역 프로퍼티는 window를 생략하고 참조할 수 있음
console.log(window.Infinity === Infinity); // true

// 양의 무한대
console.log(3 / 0); // Infinity
// 음의 무한대
console.log(-3 / 0); // -Infinity
// Infinity는 숫자값이다
console.log(typeof Infinity); // number
```

#### NaN

**예제 21-13**

```js
console.log(window.NaN); // NaN

console.log(Number("xyz")); // NaN
console.log(1 * "string"); // NaN
console.log(typeof NaN); // number
```

#### undefined

**예제 21-14**

```js
console.log(window.undefined); // undefined

var foo;
console.log(foo); // undefined
console.log(typeof undefined); // "undefined" (문자열)
```

### 21.4.2 빌트인 전역 함수

#### eval

`eval` 함수는 자바스크립트 코드를 나타내는 문자열을 인수로 전달받아 평가하거나 실행한다.

```text
/**
 * 주어진 문자열 코드를 런타임에 평가 또는 실행한다
 * @param {string} code - 코드를 나타내는 문자열
 * @returns {*} 문자열 코드를 평가 실행한 결과값
 */
 eval(code)
```

**예제 21-15**

> 다음 `eval` 예제 중 `var` 선언이 호출 스코프에 보이는 사례는 일반 스크립트의 비엄격 모드에서 실행한 직접 `eval`을 기준으로 한다. ES 모듈에서는 결과가 달라질 수 있다.

```js
// 표현식인 문
eval("1 + 2; "); // 3
// 변수 선언문
eval("var x = 5;"); // undefined

// 비엄격 모드의 직접 eval에서 var x가 호출 위치의 스코프에 선언된다
console.log(x); // 5

// 객체 리터럴을 표현식으로 평가하려면 괄호로 둘러싼다
const o = eval("({ a: 1 })");
console.log(o); // {a: 1}

// 함수 표현식을 평가하려면 괄호로 둘러싼다
const f = eval("(function() { return 1; })");
console.log(f()); // 1
```

`eval`은 마지막으로 평가된 표현식의 완료 값을 반환할 수 있다.

**예제 21-16**

```js
eval("1 + 2; 3 + 4;"); // 7
```

**예제 21-17**

```js
const x = 1;

function foo() {
  // eval 함수는 런타임에 foo 함수의 스코프를 동적으로 수정
  eval("var x = 2;");
  console.log(x); // 2
}

foo();
console.log(x); // 1
```

비엄격 모드의 직접 `eval`은 호출 위치의 스코프에 `var` 선언을 추가할 수 있다. 반면 엄격 모드의 직접 `eval`은 `var` 선언을 평가 코드 자체의 스코프로 제한한다.

**예제 21-18**

```js
const x = 1;
function foo() {
  "use strict";

  // strict mode에 eval 함수는 기존의 스코프를 수정하지 않고 eval 함수 자신의 자체적인 스코프를 생성
  eval("var x = 2; console.log(x);"); // 2
  console.log(x); // 1
}

foo();
console.log(x); // 1
```

`eval` 문자열 안의 `let`, `const` 선언은 해당 평가 코드의 렉시컬 바인딩으로 관리된다. `let`이나 `const`를 사용했다는 사실만으로 모든 `eval` 코드가 엄격 모드가 되는 것은 아니다. 외부 입력을 코드로 실행하면 보안상 위험하고 최적화에도 불리하므로 일반적인 애플리케이션에서 `eval` 사용을 피한다. JSON 데이터는 `JSON.parse`로 처리한다.

#### isFinite

전역 `isFinite`는 인수를 숫자로 변환한 뒤 유한한 숫자이면 `true`를, 무한대 또는 `NaN`이면 `false`를 반환한다.

**예제 21-20**

```js
// 인수가 유한수면 true를 반환한다
isFinite(0); // true
isFinite(2e64); // true
isFinite("10"); // true: '10' -> 10
isFinite(null); // true: null -> 0

// 인수가 무한수 또는 NaN으로 평가되는 값이면 false를 반환
isFinite(Infinity); // false
isFinite(-Infinity); // false

// 인수가 NaN으로 평가되는 값이면 false를 반환
isFinite(NaN); // false
isFinite("Hello"); // false
isFinite("2005/12/12"); // false
```

`null`은 숫자로 변환하면 `0`이므로 전역 `isFinite(null)`은 `true`를 반환한다.

#### isNaN

전역 `isNaN`은 인수를 숫자로 변환한 다음 `NaN`인지 검사하여 불리언 값을 반환한다.

**예제 21-22**

```js
// 숫자
isNaN(NaN); // true
isNaN(10); // false

// 문자열
isNaN("10"); // false: "10" -> 10
isNaN("blabla"); // true: 변환 결과 NaN
isNaN(""); // false -> 0

// 불리언
isNaN(true); // false: true -> 1
isNaN(null); // false: null -> 0
```

#### parseFloat

`parseFloat`는 문자열 인수를 부동 소수점 숫자로 해석하여 반환한다.

**예제 21-23**

```js
// 문자열을 실수로 해석하여 반환
parseFloat("3.14"); // 3.14
parseFloat("10.00"); // 10

// 공백으로 구분된 문자열은 첫 번째 문자열만 변환
parseFloat("34 45 56"); // 34

// 첫 번째 문자열을 숫자로 변환할 수 없으면 NaN을 반환한다
parseFloat("He was 40"); // NaN
```

#### parseInt

`parseInt`는 문자열 인수를 정수로 해석하여 반환한다.

**예제 21-24**

```js
// 문자열을 정수로 해석하여 반환
parseInt("10"); // 10
parseInt("10.123"); // 10
```

두 번째 인수로 기수(2~36)를 전달할 수 있다. 반환 타입은 `number`이며, 기수는 문자열의 해석 기준일 뿐 숫자 값 자체가 특정 진법으로 저장되는 것은 아니다.

**예제 21-26**

```js
// 10을 10진수로 해석하고 결과를 10진수 정수로 반환
parseInt("10"); // 10
// '10'을 2진수로 해석하고 결과를 10진수 정수로 반환
parseInt("10", 2); // 2
// '10'을 8진수로 해석하고 결과를 10진수 정수로 반환
parseInt("10", 8); // 8
// '10'을 16진수로 해석 결과를 10진수 정수로 반환
parseInt("10", 16); // 16
```

숫자를 특정 진법을 나타내는 문자열로 변환하려면 `Number.prototype.toString` 메서드를 사용한다.

**예제 21-27**

```js
const x = 15;

// 10진수 15를 2진수로 변환하여 결과를 문자열로 반환
x.toString(2); // '1111'
// 문자열 '1111'을 2진수로 해석하고 결과를 10진수 정수로 반환
parseInt(x.toString(2), 2); // 15
```

#### encodeURI / decodeURI

`encodeURI`는 URI 문자열에서 인코딩이 필요한 문자를 퍼센트 인코딩한다. `decodeURI`는 그 결과를 다시 디코딩한다. URI 전체를 처리하는 `encodeURI`와, 개별 쿼리 값 등을 처리하는 `encodeURIComponent`는 구분해서 사용한다.

### 21.4.3 암묵적 전역

**예제 21-37**

> 예제 21-37~21-39는 브라우저의 일반 스크립트에서 strict mode 없이 실행하는 경우를 전제로 한다. 각각 독립된 예제로 실행한다.

```js
var x = 10; // 전역 변수

function foo() {
  // 선언하지 않은 식별자 값 할당
  y = 20; // window.y = 20;
}
foo();

// 선언하지 않은 식별자 y를 전역에서 참조
console.log(x + y); // 30
```

비엄격 모드에서 선언하지 않은 식별자에 대입하면 전역 객체의 프로퍼티가 동적으로 생성될 수 있다. 이를 **암묵적 전역**이라고 한다. 반면 엄격 모드에서는 `ReferenceError`가 발생한다. 암묵적으로 생성된 `y`는 변수 선언이 아니므로 변수 호이스팅이 일어나지 않는다.

**예제 21-38**

```js
// 전역 변수 x는 호이스팅이 발생한다
console.log(x); // undefined
// 암묵적 전역 y는 아직 생성되지 않았으므로 읽으면 ReferenceError
try {
  console.log(y);
} catch (error) {
  console.log(error.name); // ReferenceError
}

var x = 10;

function foo() {
  // 선언하지 않은 식별자에 값 할당
  y = 20;
}
foo();

console.log(x + y); // 30
```

암묵적으로 생성된 전역 프로퍼티 `y`는 비엄격 모드에서 `delete` 연산자로 삭제할 수 있다. 반면 브라우저 일반 스크립트의 전역 `var` 선언은 일반적으로 삭제되지 않는다.

**예제 21-39**

```js
var x = 10;

function foo() {
  // 선언하지 않은 식별자에 값 할당
  y = 20;
  console.log(x + y);
}
foo(); // 30

console.log(window.x); // 10
console.log(window.y); // 20

delete x; // 삭제되지 않음 (비엄격 모드의 브라우저 일반 스크립트)
delete y; // 삭제됨 (암묵적 전역 프로퍼티)

console.log(window.x); // 10
console.log(window.y); // undefined
```

### 전역 객체와 최상위 `this` 비교

| 실행 환경              | 전역 API           | this           | 최상위 `var`가 전역 객체 프로퍼티인지 |
| ---------------------- | ------------------ | -------------- | ---------------------- |
| 브라우저 일반 스크립트 | globalThis, window | window         | 일반적으로 그렇다      |
| 브라우저 ES 모듈       | globalThis, window | undefined      | 아니다                 |
| Node.js CommonJS 파일  | globalThis, global | module.exports | 아니다                 |
| Node.js ES 모듈        | globalThis, global | undefined      | 아니다                 |

Node.js CommonJS 파일은 모듈 래퍼 안에서 실행된다. REPL이나 `node -e`의 동작을 일반 `.cjs` 파일과 같다고 가정하지 않는다.

### 숫자 검사에서 타입 변환 여부 비교

```js
console.log(isNaN("hello")); // true: 숫자 변환 결과가 NaN
console.log(Number.isNaN("hello")); // false: 문자열 자체는 NaN 숫자가 아님
console.log(Number.isNaN(NaN)); // true

console.log(isFinite("10")); // true: 숫자로 변환
console.log(Number.isFinite("10")); // false: 숫자 타입이 아님
console.log(isFinite(null)); // true: 숫자 변환 결과 0
console.log(Number.isFinite(null)); // false
```

## 복습 질문·답변

1. **Math와 JSON은 생성자 함수인가?**

   **답변:** 일반 객체다. 모든 빌트인을 `new`로 호출할 수 있는 것은 아니다.
2. **원시 문자열에 toUpperCase를 호출하면 str 변수의 타입이 바뀌는가?**

   **답변:** 아니다. 메서드 호출은 래퍼 동작으로 설명하지만 `str`은 원시 문자열로 유지된다.
3. **new Boolean(false)는 조건식에서 거짓인가?**

   **답변:** 객체이므로 참으로 평가된다. 원시 값 `false`와 구분해야 한다.
4. **globalThis와 최상위 this는 항상 같은가?**

   **답변:** 아니다. Node.js CommonJS 파일의 최상위 `this`는 `module.exports`이고, ES 모듈에서는 `undefined`다.
5. **var는 Node.js 파일에서도 global의 프로퍼티가 되는가?**

   **답변:** 아니다. Node.js 파일의 최상위 `var`는 모듈 범위에 속하므로 일반적으로 `global`의 프로퍼티가 아니다.
6. **isNaN과 Number.isNaN은 무엇이 다른가?**

   **답변:** 전역 `isNaN`은 먼저 숫자로 변환해 검사하지만, `Number.isNaN`은 타입 변환 없이 인수가 숫자 `NaN`인지 검사한다.
7. **let을 사용한 eval은 무조건 strict mode인가?**

   **답변:** 아니다. 렉시컬 선언의 범위와 strict mode 규칙은 구분해야 한다.
8. **선언하지 않은 y에 대입하면 항상 암묵적 전역이 생기는가?**

   **답변:** 비엄격 모드(sloppy mode)에서는 가능하지만, 엄격 모드(strict mode)에서는 `ReferenceError`가 발생한다.
