## 19.4 리터럴 표기법에 의해 생성된 객체의 생성자 함수와 프로토타입

객체가 상속한 기본 프로토타입의 `constructor` 프로퍼티는 일반적으로 관련 생성자 함수를 가리킨다. 그러나 `constructor`는 변경 가능한 일반 프로퍼티이므로 실제 객체 생성 이력을 보장하지는 않는다.

**예제 19-15**

```js
// Object 생성자 함수로 생성한 객체
const obj = new Object();
console.log(obj.constructor === Object); // true

// Function 생성자 함수로 생성한 함수 객체
const add = new Function("a", "b", "return a + b");
console.log(add.constructor === Function); // true

// 사용자 정의 생성자 함수
function Person(name) {
  this.name = name;
}

const me = new Person("Kim");
console.log(me.constructor === Person); // true
```

그러나 **리터럴 표기법으로 만든 객체는 생성자 함수를 `new`와 함께 직접 호출해서 만든 것이 아니다.**

**예제 19-16**

```js
// 객체 리터럴
const obj = {};

// 함수 리터럴
const add = function (a, b) {
  return a + b;
};

// 배열 리터럴
const arr = [1, 2, 3];

// 정규 표현식 리터럴
const regexp = /is/gi;
```

리터럴로 생성한 객체에서 프로토타입의 `constructor`를 조회할 수 있더라도, 그 함수가 실제로 해당 객체를 생성할 때 호출되었다고 단정할 수는 없다.

**예제 19-17**

```js
// obj는 Object 생성자 함수가 아니라 객체 리터럴로 생성했다.
const obj = {};

// 상속받은 constructor는 Object 생성자 함수를 가리킨다.
console.log(obj.constructor === Object); // true
```

`obj`는 `Object` 생성자 함수를 호출해서 만든 객체가 아니라 객체 리터럴로 생성한 객체다.

`Object` 생성자 함수를 인수 없이 호출하거나, `undefined` 또는 `null`을 인수로 호출하면 일반적으로 `Object.prototype`을 프로토타입으로 갖는 빈 객체가 만들어진다. 이 과정은 ECMAScript 사양의 추상 연산 `OrdinaryObjectCreate`와 관련된다.

**참고: 추상 연산**

추상 연산은 ECMAScript 사양에서 언어의 내부 동작을 설명하기 위해 정의한 알고리즘이다.

**예제 19-18**

```js
// 2. Object 생성자 함수에 인수가 없으면 빈 객체를 만든다.
let obj = new Object();
console.log(obj); // {}

// 1. new.target이 Object가 아닌 생성자 함수인 경우
// 인스턴스 -> Foo.prototype -> Object.prototype 순으로 체인이 형성된다.
class Foo extends Object {}
console.log(new Foo()); // Foo {}

// 3. 원시 값을 인수로 전달하면 대응하는 래퍼 객체가 만들어진다.
obj = new Object(123);
console.log(obj); // [Number: 123] (표시 형식은 실행 환경에 따라 다름)

obj = new Object("123");
console.log(obj); // [String: '123'] (표시 형식은 실행 환경에 따라 다름)
```

객체 리터럴이 평가될 때에도 `OrdinaryObjectCreate`를 통해 객체를 만들고 프로퍼티를 추가하는 절차가 정의되어 있다. 그러나 `new.target`을 확인하는지, 프로퍼티를 어떤 순서와 방식으로 추가하는지 등 세부 처리 과정은 생성 방식마다 다르다. 따라서 객체 리터럴로 만든 객체와 `Object` 생성자 함수로 만든 객체는 유사한 성질을 지니더라도 생성 과정이 동일하지는 않다.

`Function` 생성자 함수로 만든 함수는 이를 호출한 지역 스코프를 캡처하지 않고, 생성자 함수의 Realm에 해당하는 전역 환경을 사용한다. 이 점은 일반 함수 선언문이나 함수 표현식과 다르다.

**예제 19-19**

```js
// foo는 Function 생성자 함수가 아니라 함수 선언문으로 만들어졌다.
function foo() {}

// 하지만 foo가 상속한 constructor는 Function을 가리킨다.
console.log(foo.constructor === Function); // true
```

**생성자 함수와 기본 프로토타입은 연결되어 있지만, 모든 프로토타입이 반드시 생성자 함수와 한 쌍을 이루는 것은 아니다.**

객체 리터럴로 만든 객체와 `Object` 생성자 함수로 만든 객체는 일반 객체로서 비슷한 특성을 갖는다. 또한 함수 선언문으로 만든 함수와 `Function` 생성자 함수로 만든 함수는 모두 호출 가능한 함수 객체지만, 지역 스코프 캡처 등 세부 동작이 다르다.
