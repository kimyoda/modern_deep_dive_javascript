## 23.7 실행 컨텍스트와 블록 레벨 스코프

**블록에 들어갈 때 새 렉시컬 환경을 사용할 수 있으나, 일반적인 블록마다 새 함수 실행 컨텍스트가 만들어지는 것은 아니다**

```js
let x = 1;

{
  let x = 2;
  console.log(x); // 2
}

console.log(x); // 1
```

| 시점      | x 탐색의 시작 환경 |  결과 |
| ------- | ----------- | --: |
| 블록 진입 전 | 바깥 환경       |   1 |
| 블록 내부   | 블록 환경       |   2 |
| 블록 종료 후 | 복원된 바깥 환경   |   1 |

`let`, `const`는 블록 바인딩을 만든다. `var`는 일반 블록에서 새로운 함수 스코프를 만들지 않는다.

```js
function compareScopes() {
  var value = 1;

  {
    var value = 2;
    const local = 3;
    console.log(local); // 3
  }

  console.log(value); // 2
  console.log(typeof local); // undefined: 블록 바깥에서 해당 식별자를 찾지 못함
}

compareScopes();
```

블록 진입 시의 환경 준비와 TDZ도 함께 확인한다

```js
let value = 1;

try {
  {
    console.log(value);
    let value = 2;
  }
} catch (error) {
  console.log(error.name); // ReferenceError
}
```

안쪽 `value`의 바인딩이 존재하나 초기화되지 않았으므로, 바깥 값 1을 읽는 대신 ReferenceError가 발생

### 반복별 바인딩과 클로저

```js
const readers = [];

for (let i = 0; i < 3; i++) {
  readers.push(() => i);
}

console.log(readers.map((read) => read())); // [0, 1, 2]
```

`for (let i = ...)`는 반복별 바인딩을 만들어 각 함수가 해당 반복의 i를 사용. 반복문 밖의 같은 let 변수를 재사용하는 경우와 다르다.

## 질문 및 답변

1. **실행 컨텍스트의 역할은?**

   실행에 필요한 환경, 바인딩과 코드 실행 상태를 관리한다

2. **호출 스택과 렉시컬 환경은 무엇이 다른가?**

   스택은 호출, 복귀 순서, 환경은 식별자와 상위 스코프를 관리

3. **호출자의 환경이 항상 상위 스코프인가?**

   아니다. 함수가 정의된 렉시컬 환경을 기준으로 정한다

4. **var를 선언문 전에 읽으면 왜 undefined인가?**

   선언 준비 과정에서 바인딩을 만들고 undefined로 초기화하기 때문

5. **let, const도 선언문 전에 바인딩이 존재하는가?**

   존재하나 초기화되지 않아 TDZ에서 접근할 수 없음.

6. **함수 선언문과 함수 표현식의 준비 과정은 같은가?**

   함수 선언문은 함수 객체가 준비된다. var 함수 표현식의 var 값은 먼저 undefined이고 실제 대입 이후 함수가 된다

7. **블록마다 함수 실행 컨텍스트가 생성되는가?**

   아니다. 일반 블록은 같은 실행 안에서 새 렉시컬 환경을 사용할 수 있음

8. **외부 함수가 반환된 후에도 지역 값을 읽을 수 있는 이유는 무엇인가?**

   도달 가능한 클로저가 상위 환경의 필요한 바인딩에 접근할 수 있기 때문
