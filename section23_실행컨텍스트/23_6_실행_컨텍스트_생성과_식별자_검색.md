## 23.6 실행 컨텍스트의 생성과 식별자 검색 과정

실행 컨텍스트가 생성되고 코드 실행 상태가 관리되는 과정과 식별자를 검색하는 과정을 살펴보자.

**예제 23-04**

```js
var x = 1;
const y = 2;

function foo(a) {
  var x = 3;
  const y = 4;

  function bar(b) {
    const z = 5;
    console.log(a + b + x + y + z);
  }
  bar(10);
}

foo(20); // 42
```

### 23.6.1 전역 객체 생성

전역 객체는 코드가 평가되기 이전에 생성된다. 전역 프로퍼티, 전역 함수, 표준 빌트인 객체가 추가되고 동작 환경에 따라 Web API 또는 특정 환경을 위한 호스트 객체를 포함한다
브라우저의 전역 객체도 프로토타입 체인을 가지며, 그 체인의 끝은 `null`이다.

**예제 23-05**

```js
// 브라우저 일반 스크립트에서 확인
window.toString(); // 일반적인 브라우저에서 "[object Window]"

// Window의 구체적인 프로토타입 단계 수는 환경에 따라 다를 수 있음
// 확인하려면 Object.getPrototypeOf를 이용해 null까지 탐색한다
```

### 23.6.2 전역 코드 평가

다음 순서로 진행된다

1. 전역 실행 컨텍스트 생성
2. 전역 렉시컬 환경 생성
   - 2.1 전역 환경 레코드 생성
     - 2.1.1 객체 환경 레코드 생성
     - 2.1.2 선언적 환경 레코드 생성
   - 2.2 `this` 바인딩
   - 2.3 외부 렉시컬 환경에 대한 참조 결정

위 과정을 거쳐 전역 실행 컨텍스트와 렉시컬 환경이 준비된다.

**1. 전역 실행 컨텍스트 생성**

비어있는 전역 실행 컨텍스트를 생성 -> 실행 컨텍스트 스택에 푸시. 실행 컨텍스트 스택의 최상위, 실행 중인 실행 컨텍스트가 된다.

**2. 전역 렉시컬 환경 생성**

전역 렉시컬 환경을 생성 -> 전역 실행 컨텍스트에 바인딩

렉시컬 환경은 환경 레코드, 외부 렉시컬 환경에 대한 참조로 구성된다

**2.1 전역 환경 레코드 생성**

전역 렉시컬 환경을 구성하는 컴포넌트, 전역 환경 레코드는 전역 변수를 관리하는 전역 스코프, 전역 객체의 빌트인 전역 프로퍼티와 빌트인 전역 함수, 표준 빌트인 객체를 제공
ES6 이전에 전역 객체가 전역 환경 레코드의 역할을 수행. ES6 let, const 키워드로 선언한 전역 변수는 개념적인 블록 내에 존재
전역 스코프 역할을 하는 **전역 환경 레코드는 객체 환경 레코드와 선언적 환경 레코드로 구성되어 있다**

객체 환경 레코드는 var 키워드로 선언한 전역 변수, 함수 선언문으로 정의한 전역 함수, 빌트인 전역 프로퍼티, 빌트인 전역 함수, 표준 빌트인 객체를 관리
선언적 환경 레코드는 let, const 키워드로 선언한 전역 변수를 관리
전역 환경 레코드는 객체 환경 레코드 + 선언적 환경 레코드를 관리

**2.1.1 객체 환경 레코드 생성**

전역 환경 레코드를 구성하는 컴포넌트인 객체 환경 레코드는 BindingObject 객체와 연결된다.
**BindingObject는 "전역 객체 생성"에서 생성된 전역 객체다**

**전역 코드 평가 과정에서 var 키워드로 선언한 전역 변수와 함수 선언문으로 정의된 전역 함수는 전역 환경 레코드의 객체 환경 레코드에 연결된 BindingObject를 통해 전역 객체의 프로퍼티와 메서드가 된다**

등록된 전역 식별자는 전역 객체의 프로퍼티를 검색하여 찾을 수 있다. 전역 변수와 전역 함수가 전역 객체의 프로퍼티와 메서드가 되고 전역 객체의 프로퍼티를 참조 할 수 있다

**예제 23-06**

```text
var x = 1;
const y = 2;

function foo (a) {
  ...
  // 본문을 생략한 설명용 코드
}
```

x 변수는 var 키워드로 선언한 변수다. "선언 단계"와 "초기화 단계"가 동시에 진행, 코드 평가 시점에 BindingObject를 통해 전역 객체에 키로 등록한 다음 undefined를 바인딩한다
코드 실행 단계에서 선언문 이전에도 참조할 수 있다. 초기화 직후 값은 undefined고 실제 대입 이후 값은 달라지고 할당한 함수 표현식도 동일하게 동작하여 변수 호이스팅을 이해하는 데 중요한 부분이다
함수 선언문으로 정의한 함수가 평가되고 함수 이름과 동일한 이름의 식별자를 객체 환경 레코드에 BindingObject를 통해 전역 객체에 키로 등록하고 생성된 함수 객체를 즉시 할당한다. 변수 호이스팅과 함수 호이스팅의 차이다. 함수 선언문으로 정의한 함수는 선언문 이전에 호출할 수 있다

**2.1.2 선언적 환경 레코드 생성**
전역 변수와 함수 선언문으로 정의한 이외의 선언, 즉 let, const 키워드로 선언한 전역 변수(let, const 키워드로 선언한 변수에 할당한 함수 표현식 포함)은 선언적 환경 레코드에 등록되고 관리된다

개념적인 블록이 전역 환경 레코드의 선언적 환경 레코드다
전역 변수 `y`는 `const` 키워드로 선언한 변수로, 전역 객체의 프로퍼티가 되지 않기 때문에 window.y와 같이 전역 객체의 프로퍼티로 참조할 수 없다
const 키워드로 선언한 변수는 "선언 단계"와 "초기화 단계"가 분리된다. 런타임에 실행 흐름이 도달하기 전까지 **일시적 사각지대(Temporal Dead Zone)**에 빠진다.
y 변수에 대해 사용하는 `<uninitialized>`는 아직 초기화되지 않아 접근할 수 없음을 나타내는 설명용 표기다. 값이 바인딩된 것이 아니고 let, const 선언의 바인딩도 해당 스코프에 미리 만들어진다. 일시적 사각지대에 빠지기 때문에 참조할 수 없음

**예제 23-07**

```js
let foo = 1; // 전역변수
{
  // let, const 키워드로 선언한 변수가 호이스팅 되지 않으면 전역 변수를 참조해야 한다
  // 하지만 let 키워드로 선언한 변수도 여전히 호이스팅이 발생하기 때문에 참조 에러(ReferenceError)가 발생한다
  console.log(foo); // ReferenceError
  let foo = 2; // 지역변수
}
```

**2.2 this 바인딩**
전역 환경 레코드 [[GlobalThisValue]] 내부 슬롯에 this가 바인딩된다. 전역 코드에 this는 전역 객체를 가리키고 전역 환경 레코드의 [[GlobalThisValue]] 슬롯에는 전역 객체가 바인딩된다
this를 참조하면 전역 환경 레코드의 [[GlobalThisValue]] 바인딩되어있는 객체가 반환된다

전역 환경 레코드를 구성하는 객체 환경 레코드와 선언적 환경 레코드에 this 바인딩이 없고 this 바인딩은 전역 환경 레코드와 함수 환경 레코드에만 존재한다

**2.3 외부 렉시컬 환경에 대한 참조 결정**
외부 렉시컬 환경에 대한 참조는 평가 중인 소스코드를 포함하는 상위 스코프를 가리킨다. 단방향 연결 리스트인 스코프 체인을 구현한다. 평가 중인 소스코드는 전역 코드고 전역 렉시컬 환경의 외부 렉시컬 환경에 대한 참조에 null이 할당된다. 전역 렉시컬 환경이 스코프 체인의 종점에 존재한다

### 23.6.3 전역 코드 실행

변수 할당문이 실행하여 전역 변수 x, y에 값이 할당되고 foo 함수가 호출된다

변수와 함수 이름이 선언된 식별자인지 확인한다.
선언되지 않은 식별자를 읽거나 함수로 호출하면 `ReferenceError`가 발생한다. (비엄격 모드의 미선언 식별자 대입은 암묵적 전역을 만들 수 있다는 점은 별개의 규칙이다.) 스코프가 다르면 같은 이름을 가질 수 있어, 어느 스코프의 식별자를 참조하면 되는 지 결정할 필요가 있다. 이를 **식별자 결정**이라 한다.
**식별자 결정을 위해 실행 중인 실행 컨텍스트의 렉시컬 환경부터 검색한다.** 식별자의 바인딩은 렉시컬 환경의 환경 레코드에서 관리된다.
실행 컨텍스트는 전역 실행 컨텍스트이므로 식별자 x, y, foo를 검색한다. 렉시컬 환경에서 식별자를 검색할 수 없으면 상위 스코프로 이동하여 식별자를 검색한다(외부 렉시컬 환경에 대한 참조)
스코프 체인의 동작 원리다. 전역 렉시컬 환경은 스코프 체인의 종점이고 전역 렉시컬 환경에서 검색할 수 없는 식별자는 참조 에러를 발생시킨다

### 23.6.4 foo 함수 코드 평가

foo 함수를 호출하기 직전
**예제 23-08**

```js
var x = 1;
const y = 2;

function foo(a) {
  var x = 3;
  const y = 4;

  function bar(b) {
    const z = 5;
    console.log(a + b + x + y + z);
  }
  bar(10);
}

foo(20); // 호출 직전
```

1. 함수 실행 컨텍스트 생성
2. 함수 렉시컬 환경 생성
   - 2.1 함수 환경 레코드 생성
   - 2.2 `this` 바인딩
   - 2.3 외부 렉시컬 환경에 대한 참조 결정

**1. 함수 실행 컨텍스트 생성**
foo 함수 실행 컨텍스트를 생성한다. 함수 렉시컬 환경이 완성된 다음 실행 컨텍스트 스택에 푸시된다. foo 함수 실행 컨텍스트는 실행 중인 실행 컨텍스트가 된다

**2. 함수 렉시컬 환경 생성**
foo 함수 렉시컬 환경을 생성하고 foo 함수 실행 컨텍스트에 바인딩한다

**2.1. 함수 환경 레코드 생성**
함수 환경 레코드는 매개변수, arguments 객체, 함수 내부에서 선언한 지역 변수와 중첩 함수를 등록하고 관리한다

**2.2 this 바인딩**
함수 환경 레코드의 [[ThisValue]] 내부 슬롯에 this가 바인딩된다. 바인딩될 값은 함수 호출 방식에 따라 결정된다
브라우저의 일반 스크립트에서 비엄격 모드로 `foo`를 일반 호출하면 `this`는 전역 객체를 가리킨다. 이 경우 함수 환경 레코드의 `[[ThisValue]]`에는 전역 객체가 바인딩된다. strict mode에서는 일반 호출의 `this`가 `undefined`다.

**2.3 외부 렉시컬 환경에 대한 참조 결정**
foo 함수 정의가 평가된 시점에 실행 컨텍스트의 렉시컬 환경의 참조가 할당된다.
foo 함수는 전역 코드에 정의된 전역 함수다. foo 함수 정의는 전역 코드 평가 시점에 평가된다. 실행 중인 실행 컨텍스트는 전역 실행 컨텍스트다. 전역 렉시컬 환경의 참조가 할당된다.
함수를 어디서 호출했는지가 아니라 어디에 정의했는지에 따라 상위 스코프를 결정한다. 함수 객체는 상위 스코프를 기억한다. JavaScript 엔진은 함수 객체 생성 시 정의된 환경을 `[[Environment]]` 내부 슬롯으로 기억하며, 이후 호출에 그 환경을 상위 스코프로 사용한다.

### 23.6.5 foo 함수 코드 실행

foo(20) 호출에서 a는 20이 된다. foo의 지역 x에 3, y에 4가 대입되고 bar(10)을 호출한다

### 23.6.6 bar 함수 코드 평가

bar 호출의 실행 환경을 준비한다. 매개변수 b는 10을 받고, 지역 z의 바인딩을 준비한다. bar는 foo 안에서 정의되어 있으므로 상위 환경은 이 foo 호출의 환경이다

### 23.6.7 bar 함수 코드 실행과 식별자 검색

z에 5가 대입된다. a + b + x + y + z의 식별자는 다음과 같이 결정된다

| 식별자 | 찾는 환경         |   값 |
| --- | ------------- | --: |
| b   | bar의 호출 환경    |  10 |
| z   | bar의 호출 환경    |   5 |
| a   | 상위 foo의 호출 환경 |  20 |
| x   | 상위 foo의 호출 환경 |   3 |
| y   | 상위 foo의 호출 환경 |   4 |

따라서 20 + 10 + 3 + 4 + 5 = 42가 출력된다. 전역 x = 1, y = 2는 더 가까운 foo의 지역 바인딩에 가려진다

### 23.6.8 bar 실행 종료

bar의 실행 컨텍스트가 스택에서 제거되고 foo의 bar(10) 호출 다음 위치로 돌아간다

### 23.6.9 foo 실행 종료

foo의 실행 컨텍스트가 스택에서 제거되고 바깥 코드의 foo(20) 호출 다음 위치로 돌아간다

### 23.6.10 바깥 코드 실행 종료

해당 코드 단위의 실행이 끝난다. 스택에서 제거되는 것과 환경의 바인딩, 객체가 즉시 메모리에서 해제되는 것은 다르다. 클로저가 필요한 상태를 참조하면 계속 사용할 수 있다

| 단계       | 호출 스택의 논리적 상태 |
| -------- | ------------- |
| 바깥 코드 실행 | 전역            |
| foo 호출   | 전역, foo       |
| bar 호출   | 전역, foo, bar  |
| bar 종료   | 전역, foo       |
| foo 종료   | 전역            |
| 코드 실행 종료 | 해당 실행 컨텍스트 제거 |

### 선언 준비와 초기화 비교

| 선언              | 스코프 준비 시 상태       | 선언문에 도달하기 전 접근       |
| --------------- | ----------------- | -------------------- |
| var             | undefined로 초기화    | undefined를 읽을 수 있다   |
| 일반적인 함수 선언문     | 함수 객체 준비          | 호출 가능                |
| let, const      | 바인딩은 있지만 초기화되지 않음 | TDZ에서 ReferenceError |
| var에 대입한 함수 표현식 | var 값은 undefined  | 호출하면 TypeError       |

지역변수, 매개변수, this, arguments가 항상 물리적으로 하나의 단순 객체에 저장된다는 의미는 아님. 학습용 표는 식별자 탐색과 값의 차이를 설명한다
