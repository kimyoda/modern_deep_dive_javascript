# 19.8 오버라이딩과 프로퍼티 섀도잉

**예제 19-36**

```js
const Person = (function () {
  // 생성자 함수
  function Person(name) {
    this.name = name;
  }

  // 프로토타입 메서드
  Person.prototype.sayHello = function () {
    console.log(`Hi! My name is ${this.name}`);
  };

  // 생성자 함수를 반환
  return Person;
})();

const me = new Person("Lee");

// 인스턴스 메서드
me.sayHello = function () {
  console.log(`Hey! My name is ${this.name}`);
};

// 인스턴스 메서드가 호출된다. 프로토타입 메서드는 가려짐
me.sayHello(); // Hey! My name is Lee
```

생성자 함수로 객체(인스턴스)를 생성하고, 인스턴스에 메서드를 추가했다.

프로토타입이 소유한 프로퍼티(메서드 포함)를 **프로토타입 프로퍼티**, 인스턴스가 직접 소유한 프로퍼티를 **인스턴스 프로퍼티**라고 부른다. 같은 이름의 프로퍼티를 인스턴스에 추가하면 인스턴스 자신의 프로퍼티가 우선 검색된다. 이때 인스턴스의 `sayHello`가 프로토타입의 `sayHello`를 가린다.

상속 관계에서 같은 이름의 프로퍼티가 가려지는 현상을 **프로퍼티 섀도잉(property shadowing)**이라고 한다.

## 참고: 오버라이딩

상위 클래스에서 정의된 메서드를 하위 클래스에서 재정의해 사용하는 방식이다. 이 예제에서는 인스턴스의 동명 메서드가 프로토타입 메서드를 가린다.

## 참고: 오버로딩

같은 이름의 메서드를 매개변수의 타입이나 개수에 따라 구분하는 방식이다. JavaScript는 매개변수 시그니처에 따른 전통적인 오버로딩을 직접 지원하지 않지만, 매개변수나 `arguments`를 검사해 유사한 동작을 구현할 수 있다.

## 프로퍼티를 삭제하는 경우
**예제 19-37**

```js
// 인스턴스 메서드를 삭제
delete me.sayHello;
// 인스턴스에 sayHello 메서드가 없어 프로토타입 메서드가 호출
me.sayHello(); // Hi! My name is Lee
```

프로토타입 메서드가 아닌 인스턴스 메서드 `sayHello`만 삭제된다. 같은 삭제를 다시 수행해도 상속된 프로토타입 메서드는 삭제되지 않는다.

**예제 19-38**

```js
// 프로토타입 체인을 통해 프로토타입 메서드가 삭제되지 않음
delete me.sayHello;
// 프로토타입 메서드가 호출
me.sayHello(); // Hi! My name is Lee
```

`delete me.sayHello`는 `me` 자신의 프로퍼티만 삭제하고 프로토타입 프로퍼티는 삭제하지 않는다. 일반적으로 상속된 쓰기 가능한 데이터 프로퍼티에 대입하면 인스턴스에 고유 프로퍼티가 만들어질 수 있다. 상속된 setter, 쓰기 불가 프로퍼티, Proxy 등은 동작이 다를 수 있다. 프로토타입 메서드를 수정하거나 삭제하려면 프로토타입에 직접 접근해야 한다.
**예제 19-39**

```js
// 프로토타입 메서드 변경
Person.prototype.sayHello = function () {
  console.log(`Hey! My name is ${this.name}`);
};
me.sayHello(); // Hey! My name is Lee

// 프로토타입 메서드 삭제
delete Person.prototype.sayHello;
try {
  me.sayHello();
} catch (error) {
  console.log(error.name); // TypeError
}
```
