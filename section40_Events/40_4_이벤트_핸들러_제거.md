## 40.4 이벤트 핸들러 제거

### 함수 참조와 capture를 맞추기

```js
const button = document.getElementById("button");
let calls = 0;
function handleClick() {
  calls++;
}

button.addEventListener("click", handleClick, false);
button.removeEventListener("click", handleClick, true);
button.click();
console.log(calls); // 1: captrue가 달라 제거 실패

button.removeEventListener("click", handleClick, { capture: false });
button.click();
console.log(calls); // 1: 정상 제거되어 증가하지 않음
```

제거할 대상·타입·콜백 참조·capture를 맞춰야 한다. 등록과 제거에 같은 옵션 객체를 사용할 필요는 없음. once·passive 등 모든 옵션이 똑같아야 하는 것도 아님

### 익명 함수도 참조를 저장하면 제거할 수 있음

```js
const button = document.getElementById("button");
const handler = () => console.log("실행");

button.addEventListener("click", handler);
button.removeEventListener("click", handler);
button.click(); // 출력 없음
```

이름 없는 함수 자체가 문제가 아니라 나중에 같은 함수 객체를 참조할 수 있는지 중요하다. removeEventListener('click', () => ...)처럼 새 함수를 만들면 기존 함수를 제거하지 못함. bind도 호출할 때마다 새 함수가 만들어지므로 반환된 참조를 보관

### 한 번만 실행

```js
const button = document.getElementById("button");
let calls = 0;

button.addEventListener("click", function handleOnce() {
  calls++;
  button.removeEventListener("click", handleOnce);
});

button.addEventListener(
  "click",
  () => {
    calls++;
  },
  { once: true },
);

button.click();
button.click();
console.log(calls); // 2
```

첫 리스너는 실행 중 자기 참조로 제거, 둘째는 once 옵션으로 자동 제거. 첫 클릭에서 각각 한 번 실행되고 둘째 클릭에서 실행되지 않음. arguments.caller는 이 목적에 쓰지 않음

### 프로퍼티 핸들러와 AbortController

```js
const button = document.getElementById("button");
const handler = () => console.log("property");

button.onclick = handler;
button.removeEventListener("click", handler); // onclick을 제거하지 못함
button.onclick = null;

const controller = new AbortController();
button.addEventListener("click", () => console.log("listener"), {
  signal: controller.signal,
});
controller.abort();
button.click(); // 출력 없음
```

onclick 슬롯은 null 대입으로 해제. AbortController는 같은 signal에 연결한 여러 리스너를 한 번에 정리할 때 유용. abort는 이미 실행된 핸들러의 작업을 되돌리는 기능은 아님
