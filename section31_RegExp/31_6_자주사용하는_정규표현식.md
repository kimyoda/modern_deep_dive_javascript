## 31.6 자주 사용하는 정규 표현식

### 31.6.1 특정 단어로 시작 / 31.6.2 특정 확장자로 끝

```js
console.log(/^https?:\/\//.test("https://example.com")); // true
console.log(/^https?:\/\//.test("https://example.com")); // true
console.log(/^https?:\/\//.test("ftp://example.com")); // false
console.log(/\.html$/i.test("INDEX.HTML")); // true
```

URL 패턴은 접두사만 확인. 전체 URL의 유효성 검사와 구분.

### 31.6.3 숫자만 / 31.6.4 공백으로 시작 / 31.6.5 아이디

```js
console.log(/^\d+$/.test("12345")); // true
console.log(/^\d+$/.test("")); // false
console.log(/^\s+/.test(" hello")); // true
console.log(/^[A-Za-z0-9]{4,10}$/.test("abc123")); // true
console.log(/^[A-Za-z0-9]{4,10}$/.test("abc_123")); // false
```

아이디 규칙은 영문·숫자 4~10자리라는 예시 정책. 실제 허용 문자와 길이는 서비스 정책으로 정한다.

### 31.6.6. 이메일 / 31.6.7 전화번호

```js
const email = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
const phone = /^\d{3}-\d{3,4}-\d{4}$/;

console.log(email.test("user@example.com")); // true
console.log(email.test("user example.com")); // false
console.log(email.test("010-1234-5678")); // true
console.log(email.test("01012345678")); // false
```

이메일은 가독성을 위한 기본 형식 검사 예제. RFC 패턴 전체를 대싱하는 완전한 주소 검증은 아니고 실제 수신 기능 여부도 확인하지 않음. 전화번호도 외형 검사. 요구되는 형식과 인증 절차는 별도로 정한다

### 31.6.8 특수 문자 포함·제거

```js
const text = "abc#123!";

console.log(/[^A-Za-z0-9]/.test(text)); // true
console.log(text.replace(/[^A-Za-z0-9]/g, "")); // 'abc123'
console.log(/[^A-Za-z0-9]/.test("한글")); // true
```

영문·ASCII 숫자 이외의 문자. 한글도 대상이 되어 모든 상황의 특수 문자 정의로 사용하지 않음.

### 동적 검색어를 문자 그대로 사용

RegExp.escape는 ES2025 기능. 지원 환경에 입력 문자열을 정규식 패턴의 리터럴 문자열로 안전하게 표현.

```js
const keyword = "a.b";
const pattern = new RegExp(RegExp.escape(keyword));

console.log(pattern.test("a.b")); // true
console.log(pattern.test("axb")); // false
```

단순 포함 여부만 필요하면 includes 간단. 사용자가 입력한 정규식을 실행하는 기능과 입력한 문자열을 문자 그대로 찾는 기능은 다름.

## 질문 및 답변

### 1. 정규 표현식을 구성하는 두 요소

- 검색 규칙인 패턴과 동작 옵션인 플래그

### 2. 리터럴과 RegExp 생성자는 언제 구분

- 고정 패턴은 리터럴, 실행 중 구성하는 패턴은 생성자를 고려.

### 3. 생성자 문자열에 \\d처럼 백슬래시를 두 번 적는 이유는

- 문자열 리터럴의 이스케이프를 거쳐 정규식에 \d를 전달해야 하기 때문

### 4. execdp g를 붙이면 한 번에 모든 결과를 반환

- 아니다. 한 호출에 한 결과를 반환하며 반복 호출로 다음 결과를 찾음

### 5. test, match의 반환값

- test는 불리언, match는 배열 또는 null

### 6. match의 결과는 g에 어떻게 다른지

- g가 없으면 첫 결과와 캡처 등의 정보, g가 있으면 전체 일치 문자열 배열.

### 7.m과 s 차이

- m은 ^.$의 줄 경계, s는 점의 줄바꿈 포함 여부를 바꾼다

### 8. 같은 g 정규식으로 test를 반복하면 결과가 달라질 수 있는지

- lastIndex를 시작 위치로 사용, 호출 후 갱신하기 때문

### 9. A? A+차이

- 0~1회와 1회 이상

### 10. ^의 의미가 위치에 따라 어떻게 달라지는 지

- 문자 클래스 시작의 [^...]에서 부정, 클래스 밖에서 입력·줄의 시작

### 11. \w는 한글을 포함하는지

- 일반적인 \w는 영문·숫자·밑줄을 대상으로 하여 한글 전체를 포함하지 않음.

### 12. 일부 검색과 전체 형식 검사 차이

- /\d+는/ 일부 숫자를 찾아도 성공하나 /^\d+$/는 입력 전체가 숫자여야 한다

### 13. 아이디·이메일 정규식 하나가 모든 서비스에 적합한지

- 아니다. 서비스의 허용 문자·길이·지원 형식에 맞게 정하고 형식과 실제 존재 여부도 구분.

### 14. RegExp.escape가 필요한 상황은

- 동적 검색어의 점·별표 등을 정규식 기호가 아닌 문자 그대로 사용하려는 경우.

### 15. 현재 플래그 수와 u·v 관계는

- d·g·i·m·s·u·v·y의 8개이며 u와 v는 함께 사용할 수 없다
