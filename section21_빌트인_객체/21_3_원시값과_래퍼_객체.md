## 21.3 원시값과 래퍼 객체

원시 값은 객체가 아니지만, 원시 값인 문자열에서도 객체처럼 프로퍼티에 접근하거나 메서드를 호출할 수 있다.

**예제 21-04**

```js
const str = "Hello";

// 원시 타입인 문자열이 프로퍼티와 메서드를 가진 객체처럼 동작
console.log(str.length); // 5
console.log(str.toUpperCase()); // HELLO
```

원시 값을 객체처럼 사용하면 자바스크립트 엔진은 연관된 래퍼 객체를 통한 동작으로 프로퍼티에 접근하거나 메서드를 호출한다. 그 후에도 원래 값은 원시 값으로 유지된다.
**문자열, 숫자, 불리언 값에 객체처럼 접근할 때 사용되는 임시 객체를 래퍼 객체(wrapper object)라고 한다.**

**예제 21-05**

```js
const str = "hi";

// 원시 문자열의 프로퍼티에 접근할 때 String 래퍼 동작이 사용된다
console.log(str.length); // 2
console.log(str.toUpperCase()); // HI

// 프로퍼티 접근이나 메서드 호출 후에도 변수의 원래 값은 원시 값이다
console.log(typeof str); // string
```

문자열 래퍼 객체는 `String.prototype`의 메서드를 상속받아 사용할 수 있다.

프로퍼티 접근은 래퍼 객체를 사용하는 동작으로 설명할 수 있다. 식별자 `str`의 값은 접근 전후 모두 원시 문자열이다. 변수 자체가 객체로 재할당되는 것은 아니며, 엔진이 매번 실제 임시 객체를 메모리에 할당한다는 보장도 없다.

**예제 21-06**

```js
// 1. 식별자 str은 원시 문자열 값을 가지고 있다
const str = "hello";
// 2. 프로퍼티 접근에서 래퍼 동작을 사용한다. str 자체는 원시 문자열이다
// 래퍼 객체는 원시 문자열을 [[StringData]] 내부 슬롯으로 보유한다
// 비엄격 모드에서는 name 프로퍼티 대입이 지속되지 않는다
str.name = "Lee";

// 3. 식별자 str은 계속 원래의 문자열 값을 가진다
// 임시 래퍼 객체가 실제 생성되었다면 접근 종료 후 가비지 컬렉션 대상이 될 수 있다

// 4. 다음 프로퍼티 접근에서 이전 대입의 프로퍼티가 유지되지 않는다
// 새 래퍼 동작에서는 name 프로퍼티가 존재하지 않는다
console.log(str.name); // undefined

// 5. 식별자 str은 여전히 원시 문자열 값을 가진다
// 일시적으로 사용된 래퍼 객체가 있다면 더 이상 참조되지 않을 수 있다
console.log(typeof str, str); // string hello
```

숫자도 마찬가지다. 래퍼 동작에서 숫자 값은 `[[NumberData]]` 내부 슬롯으로 설명할 수 있으며, `Number.prototype`의 메서드를 사용할 수 있다. 접근이 끝난 뒤에도 변수는 원시 숫자 값을 유지한다. 래퍼 객체가 실제 생성되었다면 이후 가비지 컬렉션 대상이 될 수 있다.

**예제 21-07**

```js
const num = 1.5;

// 원시 숫자의 메서드 호출은 Number 래퍼의 동작으로 이해할 수 있다
console.log(num.toFixed()); // 2

// 프로퍼티 접근이나 메서드 호출 후에도 변수의 원래 값은 원시 값이다
console.log(typeof num, num); // number 1.5
```

ES6에서 도입된 심벌 원시 값에도 래퍼 동작이 적용된다. 다만 심벌은 일반적인 리터럴 표기법 없이 `Symbol()` 함수로 생성한다.
문자열, 숫자, 불리언, 심벌은 해당 래퍼 동작을 통해 `String`, `Number`, `Boolean`, `Symbol`의 프로토타입 메서드 또는 프로퍼티를 참조할 수 있다.
`BigInt`도 래퍼 동작을 사용한다. 반면 `null`과 `undefined`는 프로퍼티에 직접 접근할 수 없으며 `TypeError`가 발생한다.

### 래퍼 동작

| 접근 대상                            | 프로퍼티, 메서드 접근     | 주의                      |
| ------------------------------------ | ------------------------- | ------------------------- |
| 문자열, 숫자, 불리언, Symbol, BigInt | 해당 래퍼의 동작으로 접근 | 변수의 원시 타입은 유지됨 |
| null, undefined                      | 일반 프로퍼티 접근 불가   | TypeError                 |

**실행 환경 주의:** 예제 21-06의 `str.name = "Lee"`는 일반 스크립트의 비엄격 모드(sloppy mode)에서 대입이 유지되지 않는다. 엄격 모드(strict mode)에서는 `TypeError`가 발생한다. ES 모듈에서는 엄격 모드가 자동 적용된다.

```js
function assignInStrictMode() {
  "use strict";
  const text = "hello";

  try {
    text.name = "Lee";
  } catch (error) {
    console.log(error.name); // TypeError
  }
}

assignInStrictMode();
```

`Symbol`은 `Symbol()` 함수로, `BigInt`는 `BigInt()` 함수나 정수 리터럴(`10n`)로 원시 값을 만들 수 있다. 둘 다 `new`로 호출할 수 없다. 필요하면 `Object(value)`로 명시적인 래퍼 객체를 만들 수 있다.

```js
const id = Symbol("id");
const largeNumber = 10n;

console.log(typeof id); // symbol
console.log(typeof largeNumber); // bigint
console.log(typeof Object(id)); // object
console.log(typeof Object(largeNumber)); // object
```

일반적으로 문자열, 숫자, 불리언은 원시 값으로 사용한다. `new Boolean(false)`는 `false`를 감싼 **객체**이므로 조건식에서는 참으로 평가된다는 점에 주의한다.
