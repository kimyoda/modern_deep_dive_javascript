## 23.5 렉시컬 환경

렉시컬 환경은 식별자와 식별자에 바인딩된 값, 상위 스코프에 대한 참조를 기록하는 자료구조로 실행 컨텍스트를 구성하는 컴포넌트다. 실행 컨텍스트 스택이 코드의 실행 순서를 관리하면 렉시컬 환경은 스코프와 식별자를 관리한다.

렉시컬 환경은 키와 값을 갖는 객체 형태의 스코프(전역, 함수, 블록 스코프)를 생성하여 식별자를 키로 등록, 식별자에 바인딩된 값을 관리한다. 렉시컬 환경은 스코프를 구분하고 식별자를 등록하고 관리하는 저장소 역할을 하는 렉시컬 스코프의 실체다

생성 초기에 LexicalEnvironment 컴포넌트와 VariableEnvironment 컴포넌트는 동일한 렉시컬 환경을 참조한다. 몇 가지 상황 이후에 새로운 렉시컬 환경을 생성, 이때 둘의 컴포넌트는 내용이 달라지는 경우도 있다

### 1. 환경 레코드(Environment Record)

스코프에 포함된 식별자를 등록하고 등록된 식별자에 바인딩된 값을 관리하는 저장소다. 환경 레코드는 소스 코드의 타입에 따라 관리하는 내용에 차이가 있다

### 2. 외부 렉시컬 환경에 대한 참조(Outer Lexical Environment Reference)

외부 렉시컬 환경에 대한 참조는 상위 스코프를 가리킨다. 함수의 상위 스코프는 호출 위치가 아니라 함수가 정의된 환경을 기준으로 결정된다.

외부 렉시컬 환경에 대한 참조로 단방향 링크드 리스트인 스코프 체인을 구현한다.
즉, 자바스크립트가 식별자를 찾을 때 **내부 → 외부 → 전역** 순으로 단방향 연결 구조를 따라 검색한다.

### 호출 스택과 스코프 체인을 분리해서 확인

```js
const value = 1;

function read() {
  return value;
}

function caller() {
  const value = 10;
  return read();
}

console.log(caller()); // 1
```

| 비교               | 관계                                    |
| ---------------- | ------------------------------------- |
| 호출 순서            | 바깥 코드가 caller를 호출하고 caller가 read를 호출  |
| read 변수 검색       | read 환경에서 찾지 못한 value를 정의된 바깥 환경에서 검색 |
| caller의 지역 value | read의 상위 스코프가 아니므로 사용하지 않음            |

스택에서 바로 아래에 있는 호출자의 환경이 언제나 함수의 상위 스코프가 되는 것은 아님
