# 47장 에러 처리

> **예상 가능한 예외 상황은 반환값을 검사, 실행을 계속할 수 없는 실패는 던지거나 상위에서처리. 에러를 잡은 곳에서 복구할지, 로그를 남길지, 다시 전달할지 결정**

## 47.1 에러 처리 필요성

선언되지 않은 함수 호출처럼 실행 중에 예외가 발생하면 현재 실행 흐름이 중단. 예외를 적절히 처리하면 그 뒤의 코드를 계속 실행할 수 있음. 처리되지 않은 예외가 브라우저 전체나 모든 실행을 반드시 종료시키는 것은 아님. 브라우저에서 해당 스크립트나 콜백이 중단될 수 있고, Node.js에 처리되지 않은 동기 예외가 기본 동작에 따라 프로세스를 종료 시킬 수 있음

```js
console.log("[Start]");

try {
  missingFunction();
} catch (error) {
  console.error(error.name); // ReferenceError
}

console.log("[End]"); // 예외를 처리했으므로 실행
```

API는 찾는 값이 없을 때 예외 대신 약속된 값을 반환하기도 한다. 메서드 반환 규칙을 보고 처리

| 상황                                     | 결과                                     | 대응                                  |
| ---------------------------------------- | ---------------------------------------- | ------------------------------------- |
| 유효한 CSS 선택자와 일치하는 요소가 없음 | `querySelector`가 `null` 반환            | 조건문 또는 옵셔널 체이닝             |
| CSS 선택자 문법이 잘못됨                 | `SyntaxError`라는 이름의 `DOMException`  | 선택자를 고치거나, 외부 입력이면 검증 |
| 배열에 항목을 찾지 못함                  | `find`는 `undefined`, `findIndex`는 `-1` | 메서드별 반환값을 확인                |
| `null` 프로퍼티를 읽음                   | `TypeError` 발생                         | 접근 전에 값이 있는지 확인            |

```js
const button = document.querySelctor("#save");

// 버튼이 선택 사항이면 없어도 넘어감
button?.classList.add("disabled");
```

`?.`는 왼쪽 값이 `null` 또는 `undefined`일 때 접근을 건너뜀. `querySelector` 호출 자체가 던지는 선택자 문법 오류까지 막지는 못함. 반드시 있어야 하는 버튼이면 원인을 드러내는 편이 좋음
